## 机械错误（症状 / 根因 / 修复建议，按成本升序）

### 1. 派令指针未经亲核即发（本线三现形，最高优先）
- 症状：①C6 派令指 lead-review.md 的「S-3/ST-2 复核点」——文件实无此标记，追令项作废；
  ②C5 派令称「红绿同盘单提交，C3 先例形态」——git 史亲核 C3 实为红绿分盘（ac5c253/cc3dcb1），措辞失实入评审报告；
  ③C12 收口派令净差自检命令基点给 3010ad8，施工方实际基 5cfb2b9（自行拉齐后无害，但派令指针失准）。
- 根因：从会话摘要转抄指针/史实，未经 git 亲核。摘要是二手压缩件，指针类信息（文件:行/标记名/提交号/先例史实）在压缩中最易失真。
- 修复建议（成本低、立即可行）：发令前 checklist 加一条「指针类信息一律 git/grep 亲核后落笔」——标记名 grep 文件、先例 git show 亲证、基点 rev-parse 确认。判断题变流程动作。

### 2. 合并并集解动签名/结构后未扫测试锚字面量
- 症状：tc5 并入集成线时 onBurnout 签名三参→四参（并集解取 C5 侧），C11 三锚静态网用签名字符串 `onBurnout: (x, y, z) => {` 做 indexOf 锚——失配红，门禁才抓到（合并收尾提交 5cfb2b9 修锚）。
- 根因：并集解的检查面只有「两侧行都留」，没意识到签名演进对「以源码字符串为锚的守门测试」的波及。
- 修复建议：合并冲突解动过任何函数签名/结构时，提交前 `grep -n "被改签名前缀" test/` 扫一遍锚字面量；合并 checklist 固化此步。可升格进 conventions §7 合并纪律。

### 3. 「台账」术语两套口径致专项面 6/7 丢失
- 症状：C12 派令下发「台账 7 项」（遗留裁量项清单），施工方回执与报告 §0 把票面任务分解当成了台账——6 项裁量项无落点，评审疑点 B 才抓回，追令补节（2b1b7e2）。
- 根因：派令用「台账」一词无定义，票面本身有「验收标准 3 条」易联想混同；回执要求里也没有「逐项回写」的硬格式。
- 修复建议：派令专项清单用固定标签（如「遗留裁量项（逐项处置落点回写）」）并给编号；回执模板加「派令专项清单逐项对账表」硬要求。

### 4. run-green.js 红因计数按 Error 类名词频误计
- 症状：测试标题含「TypeError」字样即被计入装具炸嫌疑（C11 红因日志、C12 red-cause.log 两度现形，failed_tests 同测试重复列）。
- 根因：.scratch/run-green.js:26-28 用全文 matchAll 数类名词频，没限定堆栈行。
- 修复建议（已给修法）：只匹配 `^\s+at ` 前的类名行。实体已入库，升格为正式工具时落修。

## 环境债（缺的确定性检查/规范，只进不出须闭环）

### 5. 红绿同盘提交形态无裁判依据（C5 STD-1）
- 症状：C5 红绿同盘单提交（7b6902a），红态不可从 git 史独立复现，可审计性靠 .scratch TAP 日志补偿；派令误称有先例背书。评审建议：要么回归分盘，要么「同盘须附基线 SHA+TAP 红日志」明文升格进 conventions §7。
- 建议：retro 后由维护线裁量升格条款。

### 6. kit 键形纪律升格 conventions §1 系（C5 裁决沉淀）
- 症状：campfire-kit 燃尽回调第 4 参当下场景重拼 → 跨图漂移出裸键（8b15782 修复）。头注已沉淀（c8d77af），仓库级条款未升格。
- 条款方向：「台账条目键=身份：凡从条目反查键（回调/收尾/核销）一律用迭代键或 step 前采样键，禁按当下场景重拼」。对 furnaces/campfires 及后续任何 Map 台账件通用。

### 7. 静态网锚的脆弱性（tc5 合并三锚红引申）
- 症状：守门测试用签名字符串 indexOf 定位源码窗口，签名演进即碎。
- 建议：新写静态网用正则/结构化定位（如 `onBurnout:\s*\(x,\s*y,\s*z(?:,\s*k)?\)`），或锚旁注释「签名演进须同步此锚」。

### 8. headless 装具两条纪律（C12 走查三红沉淀）
- rAF 突发×FRAME_MIN 节流：headless 帧驱动要用真实时间节拍（sleep 注入），帧计数等拍会假死；
- profile 污染：跨轮走查每轮新开 profile。
- 建议：升 conventions §7 headless 装具条款（后续装具票执行）。

### 9. 定稿文本滞后于改道裁定（F-2，design 线）
- 症状：spec §3.4 改道裁定（81/82 不挂 BLOCK_HINTS）未回写定稿 §6.5 判据 4，权威文本与实现相抵。
- 建议：设计线的改道裁定登记表加「回写定稿」检查步（归 design-lead 线，此处仅登记）。
