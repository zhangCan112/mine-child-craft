## 机械错误（手误/漏跑检查）

### M1 提交消息禁字符清单不完整：`~` 之外 `——` 同样触发扫描器

- 症状：收尾批提交消息含中文长破折号「——」被 portable shell scanner 以 invalid-structure 拒（2026-11-23 经理线踩两次，见 feat 线 0952dd1 前两次失败调用）；历史三处 `~`（R-4 ab2e652 一处/R-6 2308063 四处/经理线 0e9dbb1 一处）已被评审记 minor 史注登记。
- 根因：conventions §7.3 只明文「避免 ~ # em-dash（—）」，中文双字长破折号「——」未列；提交者按中文行文习惯顺手使用。
- 修复建议（成本升序）：①（零成本）§7.3 字符清单补「——」并给替代写法（逗号或冒号）；②（低成本）提交前 scan 脚本固化（项目已有消息 scan 先例，纳入收尾必跑清单）。

### M2 派令/票面数字面与实测漂移

- 症状：R-5 票面基线写 2476/2475/0/1，实开工基点已涨至 2502（他票并集所致，票面写定时点早于实开工）；R-8 前身派令称 adventure.js「+16 行」实为 +8（被评审记信息 nit）。
- 根因：派令与票面在写定时刻引用当时数字，开工时点未回填实测。
- 修复建议：①（零成本）纪律宣贯——派令基线与行数宣称一律开工时 git stat/门禁实测后回填，票面基线行加「以开工实测为准」默认注；②（低成本）票册模板基线行加实测占位符。

### M3 PowerShell 管道编码陷阱（GB 系列，2026-11-17 已记两条，本线再现变体）

- 症状变体：评审员后台 npm test 经 `Select-Object` 管道——输出需命令结束才落尾段，中程表现为「机械门仍在跑」引发等待歧义；R-5 施工红证初版经管道落盘中文消息被 GBK 误读永久损毁（mojibake），改 HEAD detached 临时 worktree+UTF-8 直写重取。
- 根因：Windows PowerShell 管道默认编码非 UTF-8；`X | Select-Object` 组合的流式语义（尾段滞后）被误读为命令卡死。
- 修复建议：①（零成本）红/绿证落盘一律 UTF-8 直写（run-green 装具惯例）固化入 conventions §7；②（低成本）长跑批查尾段改「Out-File -Encoding utf8 落盘+完成后 Get-Content」两段式，禁管道直窥。

### M4 等待期 noop 占位子代理

- 症状：评审员在等后台机械门时误发占位子任务（noop）。
- 根因：背景通知纪律（等通知不轮询不占位）在子代理栈内未内化。
- 修复建议：零成本宣贯——子代理派令里明示「等待后台结果时结束本轮，不占位」。

## 环境债（缺的确定性检查/编码规范）

### D1 跨线并行无 ADR/索引号对账检查（本线最大债）

- 症状：篝火线与主线并行期——主线把门额牌 ADR 撞号改链 0012→0017→0019（含 rename），篝火线分叉不知情在同一裁决的 0012 册上加反转注记；两线各自入册致 0019 双册（篝火烫伤/主线门额牌）；合并时 rename/edit 冲突+双册并版手工裁决（本次以 0012 回收为权威册+0019 删册+考据注搬并解决）。
- 根因：ADR「编号单调不复用」纪律只在单线内可执法，跨线并行无对账检查点；README 索引考据注已记「跨线统一重编票已立项候 PO 裁时机」——债已登记但无机械执法。
- 修复建议（成本升序）：①（低成本）conventions §1.11 补「跨线并前对账」条款：合并两线前 `git ls-tree` 比对两线 docs/adr 文件名清单，撞号/rename 差异列名后并；②（中成本）合并前对账脚本化（ADR+GLOSSARY 模块计数+README 索引三面 diff），并入收尾必跑；③（存量债）重编票候 PO 已挂，见 README 撞号总账（0012×2/0017×2 如实并记）。

### D2 合并冲突裁决无守门测试

- 症状：主线 merge 389 文件含 mesh-core 注释并装/GLOSSARY 计数 74/README 索引并版/adventure-mode.test 两线测试段拼接——全靠手工+图谱，无机械守门（GLOSSARY「一览↔正文对齐守门测试」是篝火线 R-5 建的，主线侧版本本次并合后靠全量门禁兜底）。
- 根因：文档面守门测试覆盖不全（ADR 索引 vs docs/adr 实文件清单、GLOSSARY 计数 vs 实际模块数无断言）。
- 修复建议：①（低成本）ADR 索引守门测（README 索引链接的文件必须存在+号唯一或撞号有考据注）；②（中成本）GLOSSARY 大分块计数守门测（像 R-5 一览对齐测推广到主线侧词条）。

## 正面样本（本线沉淀的实践，值得延续）

- **出生即绿正当性判据**（R-5/R-6 先例链成型）：守门兑现≠红转绿，须申报边界+判别力永红探针直证——建议入 conventions 测试纪律节。
- **复验补跑面清单模式**：全绿面备案采信+只补修复面清单（design-lead 七条）——管线复验不重复跑，流程效率样本。
- **「疑似待查」定性反转**：143 顶点 mesh 疑泄漏→排查定性反转（瞬态池非泄漏+浇熄格回收真 bug 约 3 行）——排查后再定性正是流程价值，防过度修与漏修双向。
