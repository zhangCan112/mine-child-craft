# 挖掘链路现状差距分析（代码侧事实清单）

> **目的**：为 MC 原版硬度/破坏速度/工具分级调研（`docs/minecraft-mining-hardness-research.md`）提供代码侧的现状事实底座——逐条列出本游戏挖掘链路当前实现与 Minecraft 原版口径的差异点，每条附 `文件:行号` 证据。本稿只陈述现状与差异，不修改任何代码，不重复 MC 侧考证。
>
> **口径**：
> - 读代码日期 **2026-10-23**（worktree `mining-hardness-research`）。
> - MC 对照基准（任务书给定，完整考证归研究稿）：Java 版、无附魔、站于地面、不在水中。
>   `t = hard × 1.5 / speed`（可采掘 canHarvest=true）或 `hard × 5 / speed`（canHarvest=false）；
>   `speed` = 手持工具品类与方块首选品类一致时取工具速度，否则 1（**品类对→速度生效，哪怕 tier 不够；canHarvest=false 只改 ×5 系数，不丢速度**）；
>   掉落 = 仅 `toolRequired`（需镐类）方块要求「品类对且等级够」，其余恒掉。
> - 现状公式唯一权威在 `js/craft-core.js` 的 `breakTime`（144-155 行），本游戏数值（hard/speed/tier）均已按 MC 原值或拍板过的儿童配平落表，见 §6。
>
> **差异类型图例**：`刻意`（拍板过的儿童向设计决策，有设计稿证据）· `偏差`（未登记、与 MC 或设计意图不符的实现差异）· `覆盖缺失`（现状没做到/没覆盖）。

## 1. 破坏时间公式现状（js/craft-core.js:144-155）

### 1.1 现状公式逐行

| 行 | 代码语义 | 证据 |
| --- | --- | --- |
| 判定「匹配」 | `matched = 工具品类相符 && 工具 tier ≥ 方块 tier`（kind 与 tier **任一不满足即不匹配**） | js/craft-core.js:146 |
| 判定「快通道」 | `fast = 方块无工具要求(tool==null) || matched` | js/craft-core.js:147 |
| 计时 | `raw = fast ? hard × 1.5 / 手持工具speed(徒手=1) : hard × 5`（**×5 分支完全不除工具速度**） | js/craft-core.js:148 |
| 夹取 | `time = min(8, max(0.15, raw))`，再圆整到 1e-5 | js/craft-core.js:149-152 |
| 掉落门禁 | `drops = (方块 tier === 0) || matched` | js/craft-core.js:153 |

手持非工具物品视为徒手（js/craft-core.js:145 `toolOf` 返回 null）；模式层调用时同样先过 `isTool` 过滤（js/modes/adventure.js:530）。

### 1.2 与 MC 口径的三条结构性差异

| # | 差异 | MC 口径 | 现状 | 后果 |
| --- | --- | --- | --- | --- |
| A | **×5 分支丢工具速度** | 品类对时速度乘数始终生效：tier 不足 → `hard×5/speed`（如木镐挖铁矿 3×5/2=7.5s） | kind 或 tier 任一不匹配 → 一律 `hard×5`，速度被丢（木镐挖铁矿 15s→封顶 8s） | 「拿对工具但等级不够」被罚得过重，且工具阶在 ×5 分支内完全无感 |
| B | **tier 0 但有 tool 字段的方块，徒手/错工具被误判 ×5** | 泥土/沙子/原木等非 toolRequired：canHarvest=true → 徒手也走 `hard×1.5`（泥土 0.75s） | `fast = tool==null || matched`：泥土 tool='shovel'，徒手不匹配 → `hard×5`（泥土 2.5s） | **徒手挖土系/木系比 MC 慢 2.7~3.3 倍**——这是对 6 岁孩子影响最大的一条（开局徒手砍树 8s 一段） |
| C | **tool==null 方块任何工具都加速** | 只有方块首选品类的工具加速（树叶=剪刀/锄；玻璃无加速工具；剑对二者均 speed=1） | `fast=true` 时一律除手持工具 speed（js/craft-core.js:148）——剑、锹、斧挖树叶/玻璃全都「变快」 | 语义偏差；绝对差被 0.15s 下限垫平（见 §4.3） |

另：MC 的水下 ×5 / 腾空 ×5 惩罚、急迫(Haste)增益均未建模（全项目无相关代码，属有意不做但未在附录 B 登记）；MC 换手持物会重置破坏进度，现状蓄力中途换工具只重估 `need` 不清零 `t`（js/adventure-core.js:344-350 注释与实现），儿童友好但未登记。

## 4. 工具表现状（js/items-core.js）

### 4.1 16+1 条工具与数值口径

- **16 条 = 4 阶（木/石/铁/钻）× 镐/斧/剑/锹**（js/items-core.js:83-98）+ 剪刀（:56）。
- **speed**：木 2 / 石 4 / 铁 6 / 钻 8 —— 照搬 MC（js/items-core.js:82 注释；设计稿 :191）。
- **tier**：木 1 / 石 2 / 铁 3 / 钻 4 —— MC 0-3 平移 +1（设计稿 :192）；与方块表 tier 门槛（手 0/木 1/石 2/铁 3/钻 4，js/config.js:333 注释）同一坐标系。
- **dur**：120/260/500/1500 —— MC ×2 取整（拍板③，见 §6）。
- **dmg**：剑 7/9/11/13、镐 3/4/6/8、斧 5/6/8/10、锹 2/3/4/5、空手 3 —— 按「hp≈原版×1.5」折算惯例（js/adventure-core.js:284, 306-309；设计稿 :190）。

### 4.2 剑对挖掘的加成

- 对 **tool!=null** 的方块（土/木/石系）：MC 与现状都无加速——config 的 tool 合法值只有 pick/axe/shovel/null（test/blocks-fields.test.js:100-103），剑 kind='sword' 永不匹配 → 走 ×5 分支。**一致**。
- 对 **tool==null** 的方块（树叶/玻璃/草丛/火把/树苗/麦）：现状走快通道并除剑的 speed（js/craft-core.js:147-148）——钻石剑挖树叶 0.2×1.5/8=0.0375s→**0.15s**（下限垫住）、挖玻璃 0.15s；MC 里剑对树叶/玻璃 speed=1（0.3s/0.45s）。**偏差 C**：绝对差被 0.15s 下限吸收，观感上「什么工具都比手快一档」。

### 4.3 剪刀对树叶：速度生效，但「生效」的原因与 MC 不同，且不掉树叶方块

- **速度生效吗？——生效，但是「搭便车」**：树叶 tool:null（js/config.js:384）→ `fast=true`（js/craft-core.js:147）→ 除剪刀 speed 5 → 0.06s→**0.15s**（下限）。这不是品类匹配（剪刀 kind='shears' 从不出现在方块 tool 字段里），而是 §1.2 差异 C 的副作用：**任何工具**（含速度 8 的钻石剑/钻镐）挖树叶同为 0.15s。徒手 0.3s。MC：剪刀对树叶速度 15（通用 2/羊毛 5/树叶蛛网 15 三档，见研究稿 §3.3）→ 过瞬破阈值 0.05s 即碎，其它工具 0.3s。
- **掉落不变——设计承诺未兑现**：设计稿 §3.5「剪刀：剪树叶直接得树叶方块（MC 口径）」（docs/item-crafting-design.md:267）、物品注册注释同款承诺（js/items-core.js:59 注释「剪树叶得树叶方块」、:69 `leaves` 物品「剪刀剪树叶得」）。但 `drops` 只看 `tier===0||matched`（js/craft-core.js:153），树叶 tier 0 恒 true；掉落掷骰 `rollBlockDrop` 只读方块 drop 表、不看手持工具（js/drops.js:55-64），而树叶 drop 表只有 树苗 12%/苹果 4%/木棍 8% 概率条目（js/config.js:384-385）——**没有任何剪刀分支，`leaves` 物品（js/items-core.js:69，放置型 block:7）在全部掉落表中零出现，当前无获取途径**。属覆盖缺失。

## 5. 掉落门禁现状

### 5.1 语义对照

现状 `drops = tier===0 || matched`（js/craft-core.js:153）：
- `tier===0`（恒掉）↔ MC「非 toolRequired」恒掉；
- `tier>0 && tool='pick'` 要求「品类对且等级够」↔ MC「toolRequired 且 harvest level 达标」。

即**掉落门禁的语义框架与 MC 对齐**（等级映射经 tier+1 平移后逐块一致，见 §1.3(b) 与 test/blocks-fields.test.js:110-120）。

### 5.2 逐块清单

**语义一致**（两口径掉/不掉判定相同）：

| 方块 | 门禁 | 证据 |
