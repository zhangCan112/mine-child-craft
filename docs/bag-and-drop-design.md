# 背包管理两件套设计定稿：丢弃在地上 + 大背包扩容（2026-10）

> 状态：活权威（描述当前行为）。需求来源：2026-10-28 用户口头需求——
> 「背包和物品栏里的东西太多时可以选择扔在地上，等下次从远处靠近时再自动
> 拾取回去；背包也可以扩容一次，合成逻辑自定」。两件事共享「背包管理」主题，
> 合档一篇；术语见 [GLOSSARY.md](../GLOSSARY.md) 的掉落物实体库/背包核心词条。

## §1 丢弃在地上（drop-to-ground）

**复用面**：掉落物实体库（js/drops.js）已承载挖落/怪落件的完整生命周期
（落地弹跳→贴地浮动→2.5 格真空吸附→0.6 格收集→到期静默消失），丢弃不建
第二套实体，只给 `Drops.spawn` 开第六参 `opts`。

### 1.1 引擎面（drops.js，玩法中立）

| opts 字段 | 语义 | 缺省 |
|---|---|---|
| `{vx, vz}` | 初速覆盖（丢弃=定向朝面朝方向前抛） | 随机散布 |
| `{stillT}` | 拾取静默秒（复用拒收冷却 rejectT 的倒计时） | 0 |
| `{holdFar}` | **「玩家离开过吸附圈才解锁拾取」门** | false |
| `{life}` | 逐实体存留秒 | 180（挖落件不变） |
| `{dur}` | 耐久随件（收集回调第三参原样带回） | null |
| `{thrown}` | 丢弃旗（模式层退场回收判据） | false |

**holdFar 是丢弃体验的成败点**：扔出即落在吸附圈内，若只有 stillT，1.5s 后
东西会「飞回站着不动的主人手里」——丢弃等于没丢。holdFar 语义=观察到一次
「玩家在 2.5 格外」才解锁常规拾取判定（drops.js update 内自持，无定时器）。
stillT 与 holdFar 叠加是双保险（防抛掷弹跳偶然越圈即刻武装）。

**耐久随件**：收集回调签名 `(itemId, n, dur?)`；dur 非 null 时模式层不得走
`add()`——mkStack 会把工具重铸满耐久（捡回即白得耐久=作弊），与宝箱取物
（advChestTake）同一红线：空槽直放、耐久原样。

### 1.2 UI 面（mode-kit 面板骨架，三面板统一）

面板底座 mkPanelShell 新增可选 `onDrop(槽号)` / `onArm(on)` 配置：提供者
（探险三面板）出现「🗑 丢弃」头钮；armed 态（钮点亮 + 背包格红边警示）点
背包格=整摞扔出，空格不动，再点钮/关面板收。点选搬运/入箱/入炉路径在
armed 时全部让位（wirePut 与 craft 的 cellClick 入口自查 `dropArmed()`）。
未提供 onDrop 的面板（体验馆）无钮、零行为变化。

### 1.3 模式政策（adventure.js）

- **`advDropSlot(槽号)`**：整摞 `remove` → 朝面朝方向（yaw 前向，voxel 移动
  同式）在玩家身前 1.1 格抛出，`{vx,vz: 前向×2.2, stillT: 1.5, holdFar: true,
  thrown: true, life: 600, dur}`；即存（saveBag）+ 脱手音 + toast。
- **存留期分级**：挖落/怪落件 3 分钟不变（旧口径 D6）；**丢弃件与满包余量
  件 10 分钟**（`ADV_DROP_LIFE`）——刻意存放在地上的东西比战斗副产物更耐等。
- **退场回收 `advReclaimThrown()`**：切图（advSceneLeave）/重进/退出模式三处
  `Drops.clear()` 前调用——地上未捡回的 thrown 件原样收回背包（耐久件空槽
  直放）。装不下的部分转普通掉落物留地上（摘 thrown/holdFar 旗，掐断回收
  循环，按旧口径到期）。**扔出去的东西不因退场蒸发**——本游戏没有销毁物品
  的先例（零损失红线），「丢弃」在这里只意味着「放在地上」。
- **收集**：`advOnCollect(id, n, dur?)` 增耐久件分支；普通件路径逐字不动。

### 1.4 移植伴生状态清点（conventions §1.12）

对照 MC 掉落物的状态伴生机制，逐条决定移植与否：

| MC 机制 | 本设计 | 后果登记 |
|---|---|---|
| 玩家丢弃 2s 拾取延迟（40 tick） | stillT 1.5s + holdFar 门（更强） | 站着不动不会吃回去；MC 会 |
| 掉落物 5 分钟到期 | 挖落 3 分钟（旧差异不变）/丢弃 10 分钟 | 更短/更长各按场景 |
| 掉落物存世界档，重进还在 | **不持久化**——退场即收回包（§1.3） | 跨模式不保留；等价于「离开时自动捡回」 |
| 岩浆/爆炸销毁掉落物 | 无销毁路径 | 丢弃永不损失物品 |
| q 键丢一件（整组=Ctrl+Q） | 面板点选整摞，无单件丢弃 | 6 岁口径：整摞语义更简单 |

## §2 大背包扩容（27→33，一次性）

### 2.1 容量模型（inventory-core）

背包核心改**可变容量**：容量即 `inv.slots.length`，全部规则（add/take 计数、
入包空位、serialize/deserialize）按现长度遍历——扩容=槽变长，**无第二套
代码路径**。常量：`BAG_EXPAND_SLOTS = 6`、`BAG_MAX_SLOTS = 33`；
`mkInventory(cap?)` 钳制容量到 `[HOTBAR_SLOTS, BAG_MAX_SLOTS]`。

**+6 的理由**：面板主格区是固定 6 列 CSS Grid，18 主格=3 整行，+6=恰好
第 4 整行——零布局破坏；+9 会产生半行。快捷栏（槽 0~8）不动，新增全在
主格区尾部（槽 27~32）。

**存档形状**：`inventory_save` 的 `slots` 数组长度即容量（27 基础/33 扩容档
都合法；越界长度=整包损坏回落空包）。扩容状态不需要新存档键——形状天然
持久化，ADR 0002（背包壳唯一持有该键）不受影响。

### 2.2 合成逻辑（拍板：配方自定）

- 新物品 `bag_upgrade`「大背包」🎒（items-core 纯数据一行）。
- 配方（craft-core RECIPES，station 'table'）：

  ```
  线 · · 线
  革 革 革
  革 革 革        → 大背包 ×1（2 线 + 6 皮革）
  ```

  图案借**原版 1.17 bundle 环形**（兔皮→本游戏已开放的皮革），顶行两枚线
  =提手、双行皮革=包身，孩子看得懂「这是个包」。材料刻意取**任务链自然
  产物**：皮革=牛（家图牧場）、线=蜘蛛（夜怪，弓链已教杀蜘蛛）——与宝箱
  扩容档「材料随引导进度自然到期」同思路；顺带清偿 farm-and-recipe D4
  挂账（皮革此前登记为「无出口收集品」）。
- **一次性门禁**：bag_upgrade 进 KIT_HIDDEN_RECIPES；探险 allow getter 在
  「未扩容」时放开、已顶格即隐藏。隐藏配方不参与摆放台匹配——**连误合成
  都不会发生**，不靠「用了才发现没用」。体验馆（hiddenRecipesOpen）恒可见。
- **使用**：ItemUseRegistry `bag_upgrade → [{act: 'expand_bag', icon: 'bagup',
  label: '背包扩容'}]`；执行器 `advTryExpandBag`（探险壳）：已顶格=礼貌拒绝
  不消耗（兜底话术），未顶格=就地 push 6 空槽 + 消耗手持件 + 即存 +
  `level` 晋升琶音 + TTS。手持使用恒算 attempt 不落放置（弓同口径），
  触屏专用键由 advTouchList 自动获得。

### 2.3 波及面

- 快满提醒线改容量感知：`advBagFullStep(used, armed, cap)`，阈值=容量−3
  （27 档=24 与旧值逐字等价；33 档=30）。
- 面板背包格区/一键整理（sortInv）本就按 `slots.length` 遍历，扩容零改动。
- 专注训练营共享背包（ADR 0002）：只读计数与 add 均长度无关，扩容后多出
  的格子自然可用；宝物柜/矿袋不受影响。
