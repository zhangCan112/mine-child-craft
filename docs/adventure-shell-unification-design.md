> 架构治理主题：冒险模式 ↔ 体验馆的架构统一与复用。
> 评审入口：2026-10-28 架构评审（improve-codebase-architecture 流程，HTML 报告候选 1 为终态、候选 2/3 为切片）；
> 相关词条：GLOSSARY「冒险存档 store」「冒险壳政策缝」「体验馆」「探险模式」「世界改动日志」；ADR 0002（数据隔离）、ADR 0005（本票）。
> 日期：2026-10-28 · 状态：**已交付**——U1 `ed274c3`（存档 store 收拢）· U2 `2580355`（政策缝）· U3 `da4b024`（dev store+篡改档派生）· U4 `ec256cc`（统一切换，showroom.js 912→187 行）· U5 本票（收尾：GLOSSARY 终态/showroom-design §9 移交/need 旗标展品排除）。

## 1. 背景与证据

2026-10-28 评审结论（行号为物理行，评审快照）：

- `js/modes/showroom.js`（931 行）用 **~350 行编排镜像**复制 `js/modes/adventure.js`（2583 行）：
  TNT 链 54/53、睡觉转场 59/90、近战 AI 25/44、夜怪 sweep、mouseListeners、
  init/cleanup/update 喂序骨架、onMouse 使用链（对照表 30 组，见评审记录）。
- **镜像已漂移**：HEAD `8607eac` 修的正是漏抄一处 `showroomSyncBar`（探险 `advInvMove`
  同拍镜像缺一步）——复制体必漂移的直接证据；喂序两份已有位差（sleepTick）。
- 追赶成本：v2 以来 5 张票逐段接冒险面；`docs/showroom-design.md §7 D5` 仍欠
  动态夜刷环带/骷髅箭池/完整索敌 AI/TNT 炸怪段。
- 冒险侧挡路物：存档定义集中在 adventure.js:143-250，但消费触点散布 24 个函数
  28 处；死亡切图（822-831）、睡醒设出生点（906-918）、维度门禁（2438-2450）
  三处政策焊死在编排函数里；40+ 顶层单例（加载期装配）。
- 用户的原始愿景：**体验馆 = 冒险模式的复制 + 存档数据的修改优化 + 存档固化**。

## 3. 终态架构

```
                    ┌─────────────────┐   ┌─────────────────┐
                    │ 真档 profile     │   │ dev profile      │
                    │ SyncDB 三槽+背包 │   │ 内存 store(丢弃) │
                    │ 完整政策         │   │ 篡改默认值+D5值  │
                    └────────┬────────┘   └────────┬────────┘
                             │  init 前换装（单并发，无嵌套）  │
                    ┌────────▼──────────────────────▼────────┐
                    │ 冒险壳 adventure.js（唯一实现）          │
                    │ 编排（喂序/使用链/生命周期）· kit 装配    │
                    │ 政策点全经 profile 读取 · store 面收拢   │
                    └────────────────┬───────────────────────┘
                                     │
              PlaceKit · FurnaceKit · CombatKit · ModeKit · Mobs/Drops/Daylight
```

- **profile 是缝**：存档供给（load/mark/touch/flush/tick/pagehide/saveQuest/saveChest/
  saveBag）+ 政策值（死亡政策/睡醒政策/夜怪铺法/TTS·sfx 降噪/任务记账门/站点门禁/
  隐藏配方/满包余量）+ 装载 payload（世界档六键）。真档 adapter 与 dev adapter 是
  同一 interface 的两个实现——第二个 adapter 到位，缝由假变真。
- **世界即存档（②核心）**：体验馆展馆不再是 `showroomBuild` 建场函数，而是
  showroom-core 从 SHOWROOM 布局常量**派生的 edits 账本**（含整地：footprint 列
  清至展馆地平——「玩家平整过地面再建房」的存档语义）。进场 = home 图建场 →
  journal.replay 同一条链重放展馆 edits。展馆结构（房子/地下室/炉/工作台/箱/床/
  展台/火把）全部是 edits 里的方块写入。
- **showroom.js 终态**：dev profile 装配（供给派生 + 政策值注入 + 模式注册门面）
  + 建场派生数据常量。预计 931 → ~250 行；镜像编排段全删。

## 6. 测试迁移计划（④授权范围内的决定）

1. **不动**：showroom 两文件数据隔离键扫（test/showroom-mode.test.js:288-299）——
   dev store 全内存保证源文本继续干净；冒险侧全部测试 U1–U3 期间零改动。
2. **改为行为断言**：三处源码正则（`station: () => true`/`onEdit: () => {}`/
   `questMine: () => {}`）→ 改测 dev profile 下的可观察行为（台级配方随处可摆/
   挖放不落任何真实档/击杀不计任务）。
3. **重言不变量**：「恢复原装」→「dev store 丢弃一切：进场重铸、退出无痕、
   真实四档逐字节不变」。
4. **新增**：展馆 edits 派生确定性（两次派生逐字节一致）；统一壳重放同构
   （home 图 + 展馆 edits 重放 = 旧 showroomBuild 建场结果逐块一致——迁移等价性
   的可执行表达）；U2 政策缺省等价（profile 缺省 = 现行行为的快照断言）。

## 7. 否决项（备查）

- **全量工厂化 `mkAdventure()`**：40+ 顶层单例入闭包 = 冒险 110+ 测试面全量重谈，
  唯一收益（同页双实例）无需求——单并发换装以 1/10 风险达成同等深度。
- **会话 kit 先行（评审候选 2）**：统一落地后第二壳消失，镜像编排段随之消亡，
  先抽 kit 是为即将删除的复制体投资。
- **保留每箱独立账户**：与冒险大宝箱全局账户口径分叉，统一后须两套箱政策，
  违「不造第二份实现」立馆红线；预填顶格单账户覆盖同需求。
- **手抄展馆 edits 账本**：手抄 JSON 是同步漂移根源（v1 SHOWROOM_STOCK 教训），
  edits 必须从布局常量派生。
