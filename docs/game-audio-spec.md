# 游戏音频系统重建 Spec

> 状态：本地 spec（需求方拍板不走 issue tracker，本文件即权威规格；实现工单直接引用本文件）。
> 依据：`docs/game-audio-research.md`（一手来源调研）· `docs/game-audio-plan.md`（重建方案）· 调用面基线为 feature/item-crafting @ b258ab5（TNT 密室已下线、探险模式已加入后的 6 模式现状）。

## Problem Statement

6 岁的孩子在 iPad 上玩方块乐园时，音效杂音、破音严重，越玩越劈——尤其坦克驾驶的引擎嗡鸣和竞技场大规模混战时；桌面端反而尚可。同时整个游戏没有背景音乐，合成音色（方波/锯齿蜂鸣）听起来廉价刺耳，与"真游戏"的期待不符；中文语音讲解（TTS）播出时还会和音效、（未来的）音乐互相抢。对家长而言，默认音量是否保护孩子听力、音乐素材是否有版权风险，都是悬而未决的问题。

## Solution

重建音频系统，分四层交付：

1. **除噪**：修掉 iPad 杂音的四个根因（引擎嗡鸣频段低于扬声器可重放限、压限器参数过激、节点播完不清理导致音频图膨胀、无同时发声上限）；
2. **换声**：用专业录制的 CC0 游戏素材（Kenney + OpenGameArt）替换合成音色，合成引擎降级为解码失败/file:// 的兜底路径——游戏永不哑；
3. **配乐**：按 Minecraft 的稀疏触发模型加入背景音乐（随机间隔淡入一首、模式换曲交叉淡出、TTS 说话自动让路、专注训练营无 BGM）；
4. **护听**：儿童保守响度（无"吓一跳"起音）、家长可控的音乐/音量分滑杆、素材全 CC0 零署名负担并逐条溯源。

对调用方而言 `sfx(kind)` / `engineHum(level)` 接口签名不变，全部调用点零改动。

## User Stories

1. 作为孩子，我想在 iPad 扬声器上玩游戏时听到干净的声音，这样爆炸和打斗声不会刺耳难受。
2. 作为孩子，我想连续玩十分钟竞技场（100v100 大混战）音质也不劣化，不会越玩越劈。
3. 作为孩子，我想听到像"真游戏"一样好听的音效，而不是蜂鸣器一样的电子声。
4. 作为孩子，我想在冒险时偶尔听到轻柔的背景音乐，让世界更有生命感。
5. 作为孩子，我想让音乐有留白——不是一直循环灌满，安静一会儿再响起来反而更好听（C418 验证过的情感设计）。
6. 作为孩子，我在专注训练营玩的时候，不想被背景音乐分掉注意力。
7. 作为孩子，语音讲解说话时我想听得清清楚楚，音乐要自动变小声，说完再回来。
8. 作为孩子，我切换游戏模式时，音乐要平滑过渡，不要突然掐断或突兀地换歌。
9. 作为孩子，回到主菜单时，我想听到轻柔的音乐迎接我。
10. 作为孩子，坦克引擎声要有力量感，但不要让我的耳朵难受。
11. 作为孩子，我升级/胜利时的音效要欢快有成就感，让我想再来一次。
12. 作为孩子，我被打中或失败时的音效要温和不吓人（零惩罚哲学：夸努力、不吓唬）。
13. 作为孩子，戴上耳机和用扬声器玩，声音都要好听不破。
14. 作为家长，我想用两个滑杆分别调音乐和音效音量，并且刷新后还记得。
15. 作为家长，我想默认音量就是儿童安全的保守值，不用自己先去调低。
16. 作为家长，我想游戏里的音乐全部是可自由使用的开放许可，没有版权风险。
17. 作为家长，我想知道游戏里每首音乐/音效的来源和作者可以随时查证（溯源记录）。
18. 作为开发者，我想 `sfx(kind)` 和 `engineHum(level)` 的接口签名保持不变，六十多处调用点零改动。
19. 作为开发者，我想加一种新音效 = 在声音清单注册表里加一行数据（沿用参数表驱动惯例），不需要写播放代码。
20. 作为开发者，我想发声准入（同时上限/优先级抢占/同类冷却）和音乐调度（随机间隔/交叉淡出/让路）这些决策逻辑有 Node 单测，不用在真机上试错。
21. 作为开发者，我想手滑写错音效名、素材文件路径漏放、CREDITS 漏记时，测试直接红。
22. 作为开发者，我想素材下载/解码失败、或 file:// 双击直开时自动回退到合成音，游戏永远不会哑。
23. 作为开发者，我想切后台、锁屏、来电回来后音频恢复正常，不会把挂起期间排队的音效一次性炸响。
24. 作为开发者，我想给新模式配背景音乐只需在模式注册表声明一个情绪字段，不需要懂 WebAudio。
25. 作为开发者，我想 iPad 真机上的杂音修复有明确的验收矩阵（内放/耳机 × 长时间浸泡 × 大混战），而不是"感觉好点了"。
26. 作为家长，我想孩子玩的游戏页面在旧 iPad（iOS 15~17）上也能正常出声，不用升级系统。

## Implementation Decisions

- **模块划分**（一文件一模块，遵守仓库后缀语义）：
  - `AudioRegistry`（`-registry`，清单唯一权威，纯数据+纯函数）：SFX 条目 `kind → {file 样本文件 + synth 合成定义(互锁，file 条目必带 synth 回退), 桌面增益, 触屏增益, 优先级, 同类冷却ms}`（A7 实装演进：file+synth 互锁保证永不哑——素材未就绪/fetch 失败/file:// 时自动落合成；纯合成条目仅 synth，如 level/win 仪式音）；曲目表 `trackId → {文件, 情绪, 增益}`；情绪映射 `modeId → mood`。
  - `AudioCore`（`-core`，纯决策核心，零 THREE·零 DOM）：VoiceGate（发声准入：上限内放行/超限按优先级抢占最老/同类冷却期内忽略）；MusicDirector（稀疏调度状态机：tick 推进，输出 起/停/音量 事件）；儿童响度常数表。工厂接口注入时间，决策纯函数化。
  - audio adapter（无后缀，引擎层装配）：AudioContext 生命周期（手势解锁迁入+补 `interrupted` 恢复）、总线图、素材懒加载缓存、样本播放器、合成回退解释器（现合成定义表全量迁入做兜底）、引擎嗡鸣重设计、MusicDirector 执行器、duck 执行。
- **调用面不变性**：`sfx(kind)` / `engineHum(level)` 全局函数签名与语义保持；现特效模块只保留视觉特效与提示消息，音频部分整体迁出。
- **音频图**：音效总线（触屏设备前置 ~160Hz 高通）+ 音乐总线 → 总增益(0.8) → 压限器（threshold -18 / knee 24 / ratio 8，回归"保险丝"定位）→ 输出。所有增益变化一律用时间常数平滑过渡，禁止瞬时赋值。
- **节点纪律**：每个一次性音源播完即从音频图摘除（WebKit Bug 222098 官方 workaround；渐进式爆音根因）。
- **发声上限**：同时活跃音效 触屏 ≤8 / 桌面 ≤12，超限按优先级抢占最老的一条；同类冷却沿用并按条目配置（大混战防叠加爆音）。
- **引擎嗡鸣重设计**：基频上移至 120–250Hz 可重放频段 + 带通滤波 + 轻微幅度调制补"体积感"；保留触屏增益减半政策。
- **BGM 稀疏模型**（Minecraft Wiki 触发参数 + 儿童短局缩放）：主菜单解锁后随机 5–30s 起曲；游玩中一曲播完随机 60–180s 静默再下一首；切模式 1.2s 交叉淡出后 15–45s 起曲，同情绪续播不打断；专注训练营情绪为"无"。一次性播放不循环——彻底回避帧式编码的循环接缝问题，且同时最多解码一首（省内存）。
- **TTS 让路**：语音库增加可选的说话起止钩子（依赖注入式，不破坏现接口）；音乐总线 duck 至 min(基线×音量倍率, 0.08)（0.25s ramp；让路是"只降不升"的上限——音乐倍率压低或静音 0 时，TTS 开口不得反把总线抬响），说完 0.8s 缓升回。
- **素材纪律**：只取 CC0（免署名）；统一转**单声道 AAC/m4a**（iPad Safari ≤17.3 不支持 OGG，而 Kenney 全站只有 OGG，必须转码；扬声器本就近单声道，mono 同时减半解码内存）；BGM 96kbps、短曲 128kbps；源 wav/flac 不入库；总体积预算 ≤25MB；素材目录配 CREDITS 逐条记 曲目/作者/来源URL/许可/下载日期。**红线：不使用 Minecraft/C418 官方原声（受版权保护）；不取 CC-BY-SA（传染性）。**
- **降级链**：手势解锁 → 懒加载 fetch(m4a) → 解码（callback 包装防 Safari Promise reject null）→ 样本播放；任一环失败（旧设备解码失败 / file:// 无 fetch）→ 自动回退合成解释器。
- **采样率纪律**：跟随硬件默认率不显式指定；用哪个 context 播就用哪个 context 解码；页面不引入会改硬件采样率的媒体元素。
- **响度与儿童防护**：混音目标落在 −24~−18 LUFS 区间的儿童保守下沿；每个样本播放统一加 5ms 线性淡入（防点击噪）；爆炸/受击类选起音偏软的素材版本；主菜单提供 音乐/音效 两滑杆（localStorage 记忆，默认保守值）。
- **模式情绪声明**：模式注册表每行增加 `mood` 字段（数据级扩展，不碰三重命名断言；每行必声明，是模式情绪的唯一权威——AudioRegistry 的 MOODS 仅存 `menu: 'calm'` 一键）；情绪→曲库映射（曲目 mood 字段）收在 AudioRegistry。当前六模式基线：主菜单/建造=calm，竞技场/坦克=battle，下界/探险=dark，专注=none。
- **服务端配套**：静态服务器 MIME 表补音频类型；音频资产走 ETag 协商缓存（豁免代码文件的 no-store 政策，省每次刷新重复拉 ~20MB）；音频不 gzip。
- **死键清理**：因 TNT 模式下线而已无调用点的音色（引线嘶声/铁门/水花）不迁入新清单——注册表只收活着的条目。
- **文档义务**：术语表收词（AudioRegistry / AudioCore / MusicDirector，_Avoid_ 标注特效模块里的历史音效段）；工程规范的目录宪法补资产目录一行；"音频资产入库 + 单格式 m4a + 只取 CC0"写 ADR（不可逆决策）。

## Testing Decisions

- **好测试的标准**：只测外部行为——注入时间/事件，断言工厂返回的决策与事件序列；不窥探内部状态，不 mock 不存在的协作对象。
- **缝的划分**（仅一条新缝，其余全复用既有缝模式，已与用户确认）：
  - **AudioCore 工厂接口**（唯一新缝）：VoiceGate 准入决策（放行/抢占/忽略 × 上限/优先级/冷却边界）、MusicDirector 状态机（起曲间隔随机区间、切情绪交叉淡出时序、duck 深度与爬升）。先例：quality-core 的 mk/step 工厂 + 同名单测。
  - **AudioRegistry 消费端断言**（既有 -registry 缝）：清单引用的每个素材文件真实存在；扫全部 js 源码中的 `sfx('…')` 字面量 ⊆ 清单键（漏登记即红）；CREDITS 覆盖每个资产文件；模式注册表的 mood ⊆ 曲库情绪。先例：mode-registry 测试对 index.html 逐条断言。
  - **boot 全链冒烟**（既有最高集成缝）：audio adapter 不做直测（WebAudio/DOM 依赖，遵循仓库规范"adapter 经 boot 冒烟覆盖"），由按 index.html 真实加载序的共享环境冒烟抓顶层装配错误。先例：现特效模块即此覆盖方式。
  - **语音 DI 缝**（既有）：用 fake speechSynthesis 断言 duck 钩子时序（说话起→压低→说完→回升）。先例：speech 测试。
- **真机手工验收矩阵**（无法 Node 化，不设缝，写入工单验收项）：iPad 内放 vs 耳机 × 连续 10 分钟浸泡 × 竞技场 100v100 × 一台旧 iPad（社区证据表明旧机型杂音问题显著更多）。

## Out of Scope

- 空间化/3D 音效（PannerNode 正是 WebKit 高危 bug 区，明确不碰）；
- 锁屏/控制中心媒体控制集成（MediaSession，记为后续可选增强）；
- 音量设置同步到服务器进度（localStorage 即可，不进 /progress）；
- 原创作曲或音乐制作（只用现成 CC0 素材）；
- TTS 语音本身的质量/音色改造；
- BGM 无缝循环播放（稀疏一次性模型明确不做循环，也回避了循环接缝问题）；
- 双格式资产分发（ogg+m4a 双份）；
- file:// 路径下的样本播放（file:// 固定走合成回退，这是既有降级路径承诺）；
- 把现有 16 种合成音色全部样本化（氛围/特效类音色允许保留合成，清单逐条标注即可）。
