## T-G01 数据层：物品/配方/第五槽/存档/耐久豁免/任务 q27

滑翔翼特性的纯数据地基（spec §2.1 第 1/2/3/9 项）：新物品 `glider` 注册、工作台合成
配方、装备栏第五槽与存档形状、任务链 q27。来源章节：spec §3.1（物品注册三件接线与
ITEMS 行判据形状）、§3.2（配方数据行，图案与数量已定稿）、§3.3（EQUIP_SLOTS 五槽 +
存档纪律）、§3.7（任务 q27 行文案已定稿）、§5 红线 3/4/5/9、ADR 0012（无消耗）/ 0013
（第五槽）/ 0015（配方甲案）；图标像素画与话术定稿在 UI spec §5.1–5.3（照抄施工，
不自行设计）；接线三件与守门连锁证据在 research §3/§5。

### 要求

1. **物品注册三件接线**（spec §3.1，漏一即守门红）：
   - ITEMS 行（js/items-core.js）：`armor` 判据 `{slot: 'glider', tier: 'gold',
     pts: 0, tough: 0, dur: 1}`，形状照 `helmet_leather` 行——`tier: 'gold'` 是 spec
     裁定（mkArmorDef 手持薄片六档色表取 gold 档，与 UI 金骨主色同值），`dur: 1` 是
     满值占位（wornNormalize 要求 dur>0 才能过档）；emoji fallback `🪂`。
   - ITEM_HINTS 行（js/item-hint-registry.js）：名「滑翔翼」，说明「穿上它，从高处
     跳下就会张开翅膀滑翔啦」（UI spec §5.3 定稿话术）；**不得出现耐久/损坏暗示**
     （ADR 0012）。
   - ITEM_PIX 键（js/icons.js）：`ITEM_PIX.glider = {art: GLIDER_ART, map: {...}}`，
     字符画与色板**逐字符照抄 UI spec §5.2**（16×16 已程序验证：行宽全 16、左右镜像
     对称；map 五色 g/G/+/-/w 照 §5.2 注记），不自创图案。
2. **合成配方一行**（spec §3.2，数据行形状照 craft-core RECIPES 既有条目）：
   `{id: 'glider', out: {item: 'glider', n: 1}, station: 'table', shape: {rows: [['gold_ingot', null, 'gold_ingot'], ['leather', 'gold_ingot', 'leather'], ['string', 'gold_ingot', 'string']]}}`。
   **公开配方，不进 KIT_HIDDEN_RECIPES**（spec §3.2 四条理由；与体验馆
   hiddenRecipesOpen 正交兼容）。cost 由 shapeCost 派生，不另存计费表。
3. **EQUIP_SLOTS 尾部追加 `glider`**（spec §3.3/ADR 0013）：equipment-core.js 槽表
   `['helmet','chestplate','leggings','boots','glider']`（尾部追加，数组序即 UI 序）；
   `mkWorn` 形状同步扩五键。专属不互换由 wornPut 槽校验机械成立（`armor.slot === slot`），
   零新代码；与四件盔甲互不排斥。
4. **存档形状纪律**（spec §3.3/红线 9）：payload 键名仍为 `armor`，值为五键 worn；
   encode/decode（=wornNormalize）/defaults 机械改；**老档零迁移**（wornNormalize 缺键
   补 null，无迁移脚本无提示）；存→读往返幂等。
5. **wornWear 耐久豁免（独立要求块，ADR 0012 红线的落地点——spec §5 红线 5 点名的
   实现陷阱）**：`wornWear`（equipment-core.js，战斗命中遍历**全槽**扣耐久）必须豁免
   `glider` 槽——判据旗标或槽名特判归实现线裁决。这是本票**必须落地**的独立验收项，
   不是顺手改：滑翔翼进槽表后若漏此步，任意一次战斗命中就开始磨损它直至清槽，
   直接违反 ADR 0012「任何代码路径不得扣减滑翔翼耐久」。
6. **任务 q27 链尾追加**（spec §3.7）：adventure-core.js ADV_QUESTS 尾部（q26_den_chest
   之后）追加 `{id: 'q27_glider', icon: '🪂', goal: '合成滑翔翼', target: 1, ...}`
   ——文案逐字照 spec §3.7 代码块（hint 含「4 块金锭、2 根线、2 张皮革」）；**只追加
   不插队**（老档 step 存数组下标，链尾追加是 T8 远征章验证过的兼容纪律）；不
   unlock 任何地图、不发任何物品；计数走 `craft_glider` 既有通道（配方 id 派生，零新

7. **守门测试同步**（口径见文件头「守门测试口径」）：五处已知硬编码 + 既有
   items-core 数值表测试只查标准行（加行不破，research §5）——全以 npm test 全绿为准。
   另：GLOSSARY.md「装备核心」词条的「四槽」表述随本票修订为五槽（ADR 0013
   Consequences 点名；其余 GLOSSARY 新词条归 T-G06）。

## T-G02 引擎层：滑翔物理状态机 + land 事件缝 + 落差累计

> 标签：`task`｜状态：☐ 待领取｜blocked-by：无｜blocks：T-G04, T-G05

**纪律三件**：见文件头「票面纪律」——工作目录=glider worktree；开工先全量建代码图谱
（repo_root 显式传、full_rebuild=true）；npm 独立装依赖严禁 junction；收尾
npm test + npm run lint 全绿。

### 背景

滑翔的状态权威与物理在**引擎层 voxel.js**（spec §3.4 表头声明 + §5 红线 1），本票只
造物理与事实上报，**零玩法知识**（不知 HP/物品/任务；扣血结算归 T-G05，装备接线归
T-G04）。行为契约 = spec §3.4 状态与触发总表（未装备/地面/滑翔/闩锁/游泳五态）+
ADR 0016（离地>2 格自动展翼不分起因、只缓降、取消闩锁）；land 事件缝约束 = spec
§3.5「事件缝实现约束」（research §7/§9：模式层 update 在物理之后，事后读 pos/vel
拿不到落地瞬间，必须引擎物理步内置位事件）；离地高度无现成函数但有可复用件
（research §2：`groundUnderAt` 在 mobs.js **不可引**、`groundTop` 悬空会算错、
`raycastVoxel` 可用）；参数初值 = spec §3.9 参数表。

### 要求

1. **滑翔意图 API（命名归实现线，先例 `setFly` voxel.js:226）**：引擎暴露「滑翔翼
   装备位」注入口（boolean 意图，语义="玩家背着滑翔翼"——装备判断归模式层，引擎只收
   结果）；滑翔态对外可读（getter 或 worldEvents 风格迁移标志，供模式层在展翼/收翼
   时机驱动翼显隐/音效/金边，语义锁死见 spec §4.2，接口名自由）。
2. **滑翔物理分支**：步行分支重力段旁新分支（flyMode 先例 voxel.js:264-270）。展翼
   条件 = 装备位 on + 离地 >2 格（整格比较）+ 未闩锁，**不分跳跃/走落/被击飞**；
   滑翔中垂直速度恒为缓降速率（§3.9 初值 −3.0 格/秒，高度只减不增），水平速度 =
   yaw 同源操控（§3.9 初值 5.0 格/秒，不享受疾跑）；落地触地即收翼回地面移动。
   边界：flyMode 优先（飞行中不判滑翔）；建造/竞技场装备位恒 false 即零参与。
3. **离地列探引擎内自实现**（spec §5 红线 2）：向下列探脚下地面取离地高度
   （raycastVoxel/列扫自实现或将公共件上移引擎层，归实现线裁决）；**严禁引用
   mobs.js 的 `groundUnderAt`**——voxel.js 现状不引用 mobs，引擎→应用反向依赖违反
   分层硬规则。水面判定口径照 spec §3.4「水面软着陆」：水面上空照常按展翼规则判定，
   落水即软着陆（验收绑行为不绑探测细节）。
4. **主动取消与闩锁**（ADR 0016）：滑翔中再点跳跃（Space，零新增输入通道）=立即收翼
   转无翼自由坠落 + 闩锁置位；闩锁期间高度条件**不**重展，空中再点跳跃=解除闩锁+
   主动再展；落地/入水闩锁无条件清除。
5. **land 事件缝**（spec §3.5 事件缝约束）：`worldEvents` 增 land 类事件（置位惯例
   照 voidFall/splash：voxel.js:413 声明区、每帧主循环自清 false；分发先例
   main.js:388-395），**携带本次落差与触地时滑翔态**。main.js 转发到模式层的接线归
   T-G04/T-G05，本票只保证引擎侧置位与事件数据正确。
6. **落差累计器**（spec §3.5 计量口径，钉定义）：落差 = 本次连续无翼下落段峰值 −
   落地点高度；展翼瞬间累计重置（峰值=当前高度）；主动取消/滑翔中卸翼/闩锁态坠落
   自收翼点重新累计；入水清零（splash 既有 vy 清零同点清累计）；平地跳跃（峰值
   1.42 格）恒无伤。
7. **新顶层绑定登记**：滑翔旗标/闩锁/落差累计等新 `let` 绑定登记进 voxel.js 玩家段
   头注释白名单（voxel.js:192-207，唯一权威），并按 conventions §1.10 升格判据评估
   是否纳入 conventions.test.js 守门正则（与 flyMode 同待遇，结论随票记录）。
8. **参数块**：config.js 落滑翔专属参数块或 PLAYER 区扩展（风格照 PLAYER 现表
   config.js:60-73；落点归实现线）：展翼高度阈值 2 / 缓降速率 −3.0 / 滑翔水平操控
   5.0（spec §3.9 初值，实现期可调不判需求变更）；伤害两参数（无伤阈值/每格扣血）
   由 T-G05 顺延落同一块。
