# ADR 0007 · 大宝箱两轨容量：材料阶梯保留 + 每放一箱加 9 格（放箱即扩）

日期：2026-10-28 · 状态：已采纳（用户拍板三连：+9/箱不设上限 · 两轨并存 · 容量随现存箱子数缩放）

## Context

大宝箱容量原为单一材料轨（引导链 v2 拍板：9→18 格 8 圆石→27 格 4 铁锭，顶格 27 硬上限）。
实玩反馈：材料扩容麻烦，且「造多个箱子」没有容量回报——孩子放了五个箱子，容量还是 27 格，
造箱积极性受挫。用户要求：**保持全局单账户（所有箱子打开同一份存储），但每多放一个箱子
容量就多一份**。

## Considered Options

**A. 两轨并存：材料阶梯保留 + 箱轨每箱 +9（采纳）**
总容量 = 材料阶梯基础格（9/18/27）+ 9 × 现存已放置箱子数，不设上限。材料轨继续接任务链
产物节奏（第 7/12 步自然到期），箱轨给「多造箱子」即时回报。
代价：容量成为派生值，需要定义「现存箱子数」的权威来源（见 Consequences ①）。

**B. 箱轨替换材料轨（否决）**
删阶梯只留箱轨。任务链第 7/12 步的产物消耗节奏被拆掉，且已发布的引导话术/文档全要改。
用户明确选并存。

**C. 每箱 +27（按 MC 正典一格箱 27）（否决）**
两个箱子就翻三倍，容量膨胀过快；本作一格箱的儿童心智单位是初始 9 格档（「一格箱=9 格」
与面板第一屏一致），+9 直观。

**D. 容量只增不减（挖箱不缩容）（否决）**
用户拍板「随现存箱子数缩放」。超容存量留档不丢、容量恢复自然可见，零损失口径不破坏。

## Consequences

- **①「现存箱子数」从世界账本现算，不落盘（防漂移红线）**：五个场景 edits 桶
  （`advSceneEdits`，home/desert/snow/swamp/nether）里值 `=== B_CHEST` 的条数即现存玩家
  放置的箱子。只有玩家放置/挖除进账本——结构宝箱（神殿/雪屋/女巫小屋）在确定性建场里，
  天然不计入；挖掉/ TNT 掀掉/覆盖的箱子账面变空气即除名。政策纯函数
  `advCountChestEdits(buckets)` 在探险核心（`B_CHEST` 经共享词法环境消费，与建场件同款）。
- **②增删检测挂 `advMarkEdit` 唯一记账缝**：放置/手挖/TNT 掀/覆盖全路径都经此缝
  （F1 炉退包同款先例），缝上比对记账前后的箱子态变化触发重算（`advChestResync`）。
  禁止在任何单一路径二次挂减法钩子。
- **③存档形状不变、老档零迁移**：`adventure_chest_save = {size, slots}`，`size` 字段
  语义从「总容量」收窄为「材料阶梯基础格 base」。老档无箱轨概念，base=老 size 恰好兼容；
  总容量运行态派生（`size = base + 9×chests`），`saveChest` 显式只写 `{size: base, slots}`。
- **④超容存量零损失**：slots 数组永不截断——容量缩水后第 size 格起的存量留档不可见，
  容量回来自然可见（与账户归一化既有注释同口径）。面板/`advChestPut/advChestTake`
  只认前 size 格的判据不变。
- **⑤面板两轨各一句话**：箱格下容量提示行报「现存箱子数 + 总格数」（chest() 契约扩一
  chests 字段）；材料扩容钮文案改「＋ 材料扩容（+9 格）」（阶梯加的是基础格，避免与
  总容量混淆），扩容 toast 报总容量。
- **⑥体验馆同口径修正（2026-10-28 真机验证）**：初版实现曾加 `chestCapScale` 政策缝把
  体验馆箱轨整条关掉（动机：展馆世界本身是 edits 重放，陈列仓库箱会把顶格 27 顶成 72）；
  用户真机在展馆造箱验证特性时容量不增即报——撤销该缝，陈列箱与冒险同口径逐只计入。
  篡改档语义随之收窄为「基础格顶格 27 + 陈列箱加成」（预填物资仍是 27 槽）。
  教训：体验馆是特性验证场，不为它造第二口径。
- GLOSSARY「大宝箱」词条与 `_Avoid_` 随此修订（新增两条 Avoid：账本计数器第二账本、
  两轨二选一）。
