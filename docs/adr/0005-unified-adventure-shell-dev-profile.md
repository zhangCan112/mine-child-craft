# ADR 0005 · 体验馆=统一冒险壳 + dev profile（存档供给缝），不做全量工厂化

日期：2026-10-28 · 状态：已采纳（docs/adventure-shell-unification-design.md，分票 U1–U5）

## Context

体验馆定位是「冒险全开实验室」：debug 冒险模式的场，退出恢复原装。愿景口径 =
冒险模式的复制 + 存档数据篡改 + 存档固化。现状是第二装配工：showroom.js 用
~350 行手工镜像冒险壳的编排段（TNT/睡觉/AI/喂序/使用链），每加一个冒险特性
要开票重抄，且镜像已漂移（8607eac）。冒险壳本身是加载期单例：SyncDB 槽与
journal 模块顶层实例化、存档消费触点散布 28 处、三处政策焊死在编排函数里——
「换一份存档供给、关掉持久化」这条缝不存在。

## Considered Options

**A. profile 注入 + 单壳换装（采纳）**
冒险壳保持单例顶层结构，存档供给与政策点收拢为 profile 对象（真档 adapter 缺省），
体验馆在 init 前换装 dev profile（内存 store + 篡改默认值 + D5 政策值）。
优点：40+ 顶层单例不动 → 冒险 110+ 测试面零震动；单并发运行下换装即够
（两模式永不同时 init）；U1–U3 三票行为逐字不变，风险前低后高可随时止步。
代价：壳内新增 profile 读取分支；「同页双冒险实例」永久不可得（无此需求）。

**B. 全量工厂化 mkAdventure()（否决）**
优点：任意多实例；profile 经构造期注入更纯。
缺点：2583 行壳 + 28 键 .adv 测试面 + 40+ 顶层名单全量重谈（110+ 用例连坐），
唯一收益无需求；共享词法环境下跨文件顶层名（engine 绑定直写）仍要逐一甄别。

**C. 维持镜像 + 会话 kit 收编（否决）**
只抽编排 kit 不统一壳：镜像消亡但「冒险新特性自动进馆」不成立，D5 欠账
（动态夜刷/完整 AI/下界/地图）永久欠着——与 2026-10-28 拍板③「全部子系统进馆」相抵。

## Consequences

- 存档键名唯一权威留冒险侧真档 store；dev store 全内存零键字面量——
  ADR 0002 数据隔离由 adapter 保证，showroom 两文件键扫红线不动。
- 展馆世界以冒险存档 edits 的形式形成（home 图建场 + 派生 edits 重放），
  建场函数路径退役；edits 必须从布局常量派生，禁止手抄账本。
- D5 两项拍板（原地复活、固定点位夜怪）降格为 dev profile 政策值，随缝长期保真；
  其余 D5 推迟项（完整 AI/TNT 炸怪/下界/地图）随统一自动勾销。
- 体验馆箱账户从「每箱独立内存账户」归一到冒险全局单账户口径（顶格+派生预填）。
- 本 ADR 不可逆点：统一切换（U4）删除 showroom 镜像编排段后，回退需整票还原；
  dev profile 的篡改档形状（全解锁/全顶格/房内出生）一旦落测试即成行为承诺。
