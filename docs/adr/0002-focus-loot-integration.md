# 0002 — 专注训练营接入物品系统（推翻 item-crafting-design D1 的"不接入"口径）

`docs/item-crafting-design.md` D1 拍板时把专注训练营划在物品系统接入面之外（理由：训练口径
不动）。2026-10-23 用户明确选择**更深一层**的接入：训练产出真实战利品、进真实背包存档、
跨模式可见。我们决定把 `inventory_save`（设计稿 §D2 已预留的镜像键）从"探险模式私有"升格为
**全游戏唯一共享背包**，由专注训练营做第一个消费者，并新增应用层壳 `js/backpack.js` 唯一持有
该存档键。

## Considered Options

- 只用图标做刺激与奖励观感（不落数据）—— 被否（用户拍板要收集系统）；且"赚了却看不见"
  的奖励回路对 6 岁的长期吸引力弱。
- 专注模式私有背包键 `focus_inventory_save` —— 被否：第二个消费者（探险/建造）一出现就得
  迁移合并，重演 ADR 0001 之前的"两套账本"问题。
- 共享键 `inventory_save` + 应用层壳 Backpack（采用）：一份形状、一处演化；专注只**产出**
  不**消耗**（不接配方/耐久/挖掘/放置），训练口径照旧。

## Consequences

- 未来消费方（探险模式、建造生存开关、下界掉落）必须走 `js/backpack.js`，不得自开存档键。
- 探险模式的经济设计必须消化专注时代积累的存量物品：专注掉落表以**基础材料为主**（煤/圆石/
  骨粉/线……），钻石类稀有权重低且有每日 6 关的天然产出上限（线性推进、无选关重打）。
- 工具（不并堆、带耐久字段）经里程碑授予进包，专注模式内永不消耗耐久——耐久政策仍归未来
  的消费模式。
- `item-crafting-design.md` D1 表同步修订（见其变更记录）；本 ADR 是该修订的决策依据。
