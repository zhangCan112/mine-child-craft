# 挖掘硬度修正 · 实现设计

> 需求（2026-10-23 用户原话）：「现在方块没硬度系统吗？挖什么都要好久，参考我的世界分级下有些挖的快有些挖的慢。有些东西手拿初始工具挖不了，必须造更高级的工具。我们目前还缺这套系统。」——调研结论：系统骨架**已在**（四字段 + breakTime + tier 门禁），但公式有一处结构性偏差把「偏好工具」误当「必需工具」，惩罚面扩得过大，正是「挖什么都要好久」的根因。
> 调研依据：`docs/minecraft-mining-hardness-research.md`（MC 一手口径，下文「研究稿 §n」）+ `docs/mining-gap-analysis.md`（代码侧 26 条差距，下文「差距稿 §n」）。
> 待拍板（P# 为起草建议，未确认前不动工）：
> 1. **速度与掉落解耦**（D1）：工具**品类**对 → 速度乘数生效（等级不够也生效，JE 口径）；只有「品类对且等级够」（canHarvest）才决定 ×1.5/×5 系数与掉落。泥土徒手 0.75s、原木徒手 3s、木镐挖铁矿 7.5s——全部回到 MC 口径。
> 2. **剪刀对树叶补全**（D2）：树叶 tool 字段从 null 改 'shears'（品类匹配）+ 新增 `shearDrop` 专属掉落——剪树叶掉树叶方块（兑现设计稿 §3.5 承诺，修复 leaves 物品无获取途径）。
> 3. **TNT 可回收**（D3）：探险放置的 TNT 补四字段（hard 0）——**短按=点燃**（现状行为不变），**按住=挖走回收**（MC 口径 hardness 0）；爆炸链经核实零影响（圈内 TNT 本就走链式点燃分支，不进掉落掷骰）。
> 4. **其余维持现状只登记不改**（D4/D5）：8s 封顶、0.15s 下限、连续时间（无刻量化）、环境修正不做、换工具不清进度、剑无挖掘身份——全部是已有或本设计确认的儿童向裁剪，进附录 B 登记。

## 0. 问题定义与改动面盘点

### 根因一句话

`craft-core.js` 的 `breakTime` 把 MC 的两个**正交**判定捏成了一个 `matched`：

- MC：`品类对`（→ 速度乘数，等级不看）× `canHarvest`（→ ×1.5/×5 系数与掉落门禁，研究稿 §1.2/§8 源码四段）；
- 现状：`matched = 品类对 && 等级够`，任一不满足 → 直接 ×5 且**丢工具速度**——等价于把 Bedrock 口径（研究稿 §1.4）误用进 JE 公式。

受害最大的是开局链：徒手挖泥土 2.5s（MC 0.75s）、徒手砍树顶到 8s 封顶（MC 3s）、木镐挖铁矿 15s→8s（MC 保留速度只要 7.5s）。差距稿差距总表 #1~#5 五条偏差全部由此而来。

### 改动面（小体量：两处数据 + 一处公式 + 一处掉落可选参 + 一处输入判定）

| 改动 | 文件 | 性质 |
| --- | --- | --- |
| breakTime 公式拆正交 | js/craft-core.js（144-155 行，~4 行改动） | 修正（接口签名不变） |
| 树叶 tool:'shears' + shearDrop 字段 | js/config.js（7 号方块一行 + shearDrop 字段语义） | 修正 + 补全 |

## D1 · breakTime 公式修正：速度与掉落拆正交（待拍板 ①）

```js
/* 修正后（craft-core.js breakTime，接口签名不变，仍返回 {time, drops}） */
const kindMatch = !!(tool && blockDef.tool && tool.kind === blockDef.tool);   // 只看品类
const speedMult = kindMatch ? tool.speed : 1;          // 品类对 → 速度生效（等级不够也生效, JE 口径）
const canHarvest = blockDef.tier === 0 ||
    (kindMatch && tool.tier >= blockDef.tier);         // 掉落门禁 = 品类对且等级够
const raw = blockDef.hard * (canHarvest ? 1.5 : 5) / speedMult;
const time = Math.min(8, Math.max(0.15, raw));
return {time: Math.round(time * 1e5) / 1e5, drops: canHarvest};
```

| 方案 | 说法 | 取舍 |
| --- | --- | --- |
| **A. JE 正交口径**（定稿建议） | 品类管速度、canHarvest 管系数与掉落 | 与 MC Java 一致（研究稿 §8 源码 `DiggerItem` 双判定）；「拿对工具但等级不够」仍有 ×10/3 惩罚与无掉落，教学梯度保留；修正面恰好覆盖差距稿 #1~#5 |
| B. 维持现状（Bedrock 口径） | 速度归 1 | 「挖什么都要好久」的根因，用户已否 |
| C. 顺手引入 MC 刻量化（ceil 到 1/20s） | 对齐 Wiki 表值（1.15s 而非 1.125s） | 增加概念不改体验，研究稿 §10.6 判「不对齐则全用理论值」——维持连续时间，登记附录 B |

要点：

- **`tool:null` 方块（树叶/玻璃/草丛类）从此任何工具都不加速**（kindMatch 恒 false）——现状的「任意工具 ×speed」（差距稿差异 C）随之消失，玻璃从 0.15s 回 0.45s。剪刀对树叶的加速改由 D2 的品类匹配承担，语义归位。
- 剑从此对一切方块无加成（MC 通用 ×1.5 的裁剪，见 D4）。
- drops 公式形状不变（`tier===0 || 品类对且等级够`），**掉与不掉的判定结果逐块不变**——变化只在时间侧（速度生效条件放宽、×5 系数只挂在采集失败上），TTS「需要更硬的镐子」链路零改动。

## D2 · 剪刀对树叶：品类匹配 + shearDrop 专属掉落（待拍板 ②）

两处配套：

1. **config.js 树叶(7)**：`tool: null → 'shears'`（品类匹配 → 剪刀速度 5 生效：0.2×1.5/5=0.06s→0.15s 下限；徒手/其它工具回 0.3s，MC 同款节奏）+ 新字段 `shearDrop: [['leaves',1,0]]`。
2. **drops.js rollBlockDrop(blockDef, rand?, toolStack?)**：追加可选第三参——手持剪刀且方块有 shearDrop → 掷 shearDrop 表替代默认表（掷骰语义归掉落物实体库，GLOSSARY「掉落表掷骰写在模式层」反例防线）。探险破坏结算（adventure.js:511）改为 `rollBlockDrop(BLOCKS[id], null, held)`；**TNT 爆炸路径（adventure-core.js:465）不传工具**——掀树叶走默认概率表，MC 口径，零改动。

| 方案 | 说法 | 取舍 |
| --- | --- | --- |
| **A. tool:'shears' + shearDrop 字段**（定稿建议） | 品类匹配走 D1 既有通道；专属掉落是显式数据 | 加字段不加语义分支；爆炸路径天然回落；兑现物品与合成设计稿 §3.5「剪树叶直接得树叶方块」承诺（差距稿 #24） |
| B. drop 表加工具条件条目 | `['leaves',1,0,'shears']` 条目级开关 | 掉落条目形状复杂化，所有消费方都要判第五位，防错网跟着大改 |
| C. 不修（leaves 物品继续无来路） | — | 树叶作为放置型物品已注册（items-core）却永远拿不到，僵尸数据 |

配套口径：`shearDrop` 的 tool 合法值放开（test/blocks-fields 的 tool 枚举断言 `pick/axe/shovel/null` → 加 `'shears'`）；剪刀 speed 维持 5 不改（树叶档 MC 为 15，但 0.15s 下限把两者垫成同一观感，改数值无收益，登记附录 B）；剪刀耐久维持 500（MC 238×2≈476，工程推定值不动）。

## D3 · TNT 可回收（待拍板 ③）

```js
/* config.js B_TNT(20) 补一行（只增不改既有旗标） */
BLOCKS[B_TNT] = { ..., hard: 0, tool: null, tier: 0, drop: [['tnt', 1, 0]] };
```

- **交互二分（短按点燃 / 按住挖走）**：现状是 onMouse 左键在 mousedown 瞬间点燃并 return（adventure.js:1118-1121 拦截在最前），「按住挖」进不了蓄力链——需把点燃改为 **pending 判定**：按下 TNT 记 `{坐标, 时刻}` 不点燃；松手间隔 < 0.25s → 点燃（与现状短按体感逐点一致）；按住 ≥ 0.25s → 进入蓄力（hard 0 → 0.15s 挖走，掉 tnt 物品回收）。触屏单击政策天然同款（tap=点燃）。这是纯增量：今天一切「点击点燃」的行为保持不变，只新增「按住拿回来」。
- **爆炸链零影响（已核实）**：advExplode 对圈内 TNT 走链式点燃分支并 continue（adventure.js:870-872），根本不进掉落掷骰；源块也是直接清除不掷骰（:861）。补 drop 字段不改变任何爆炸行为。为守住「TNT 不自掉」不变量与字段解耦，advTntRoll 加一行守卫 `if (def.tnt) return []`（原靠「无 drop 字段」隐式成立，adventure-core.js:460 注释同步改写）。
- 任务链零牵动：QUESTS 12 步主线无 TNT 步（q1~finale 全是采集合成链，adventure-core.js:495-547），点燃话术与 TTS 在 TNT 行为链测试内自洽更新。
- blocks-fields 的 GATHER 断言集补 20 号（四字段形状 + hard 0 + drop 掉自身）。

## 附录 A · 修正后 breakTime 语义速查

```
输入: blockDef {hard, tool, tier, drop, shearDrop?} × toolStack {id} | null（徒手/非工具）
品类匹配 kindMatch = 手持工具 kind === 方块 tool（null 方块恒 false）
速度 speedMult    = kindMatch ? 工具 speed : 1          ← 品类对就生效, 等级不看（JE）
采集 canHarvest   = tier === 0 || (kindMatch && 等级够)  ← ×1.5/×5 系数与掉落门禁
耗时 t = hard × (canHarvest ? 1.5 : 5) / speedMult, 钳 [0.15, 8]
掉落 drops = canHarvest；表选择 = 剪刀×shearDrop 存在 ? shearDrop : drop
```
