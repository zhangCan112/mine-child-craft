## 1. 概述与验收锚

**验收锚（R1 拍板集合的具象画面，置顶）**：孩子在家门口用木棍、原木和一块煤炭合出
篝火，放下就燃（不用点火），火光很大、烟柱升起来；穿着滑翔翼站到火边一跳——
「噗」地展开翅膀，顺着热气一路升过山头；约 5 分钟后火烧完，地面干干净净什么都不剩
——「家门口的起飞器」。

篝火是**探险模式专属（体验馆同口径开放）**的可合成**消耗品**方块道具：大光源
（light 15）+ 热气流源 + 顺手的防御工事（怪物也怕火，R2-2）；**纯玩具**——零任务引导、
零话术剧透，玩法完全靠自然发现（⭐R1-13，PO 改推荐：推荐接任务被否）。
滑翔契约（ADR 0016「无任何爬升手段」）由 ADR 0017 显式修订为「**气流柱外**无任何
爬升手段」——乘热气流上升是滑翔翼唯一爬升手段，本期唯一气流源=燃烧中的篝火。

**整体验收口径**：§3 各功能块验收标准全过 + §5 设计定稿走查项全过 + `npm test`
全绿（含规范守门）+ `npm run lint` 零错误 + `node server.js` 手工走查验收锚画面。

## 2. 范围声明

### 2.1 范围内（本期做）

1. 篝火物品注册（ITEMS / ITEM_HINTS / ITEM_PIX 三件接线，§3.1）。
2. 工作台 3×3 配方：木棍×3 + 原木×3 + 煤或木炭×1（候选数组格子）→ 产量 ×2（§3.2）。
3. 方块两态（燃烧/熄灭两个方块 id）+ 放置规则（实体方块顶面，放置即燃，§3.3）。
4. 生命周期状态机：燃尽干净消失（⭐R1-06）/ 水浇转熄灭态 / 点击重燃重置时长 /
   任意态挖掘回收 / 随档恢复余时（§3.4、§3.8，ADR 0018）。
5. 热气流引擎层可复用机制（`updraft-core` 纯核心）+ 乘流（ADR 0017 例外两处：
   柱内唯一爬升手段、柱内跳跃展翼豁免）（§3.5）。
6. 烫伤：踩燃烧中篝火每满 1 秒 1 血，玩家+怪物同规则（ADR 0019）（§3.6）。
7. 光照 light 15 / 烟与火焰与气柱表现（行为面）/ 音效两枚 / ItemHint 基础说明
   不剧透（⭐R2-3）（§3.7）。
8. 体验馆同口径（dev store 惯例，§3.8）。

### 2.2 范围外（明确不做）

| 不做项 | 依据 |
|---|---|
| 建造/竞技场模式接入（火把/灯块照明已够用） | R1-01 |
| 篝火烤肉（生熟肉走熔炉现有链路；天然二期候选） | R1-16 |
| 雨天熄灭（项目无天气系统——daylight-core 单晴天区间，课题整条不存在） | 事实底座 |
| 任务链接入（含 q28 及任何计数消费） | ⭐R1-13 |
| 点火道具/点燃动作（全表无打火石；放置即燃零新增交互） | R1-04、事实底座 |
| 加柴/燃料格/堆柴起流门槛（BotW ≥4 捆机制不移植） | 有意偏离，§10 附录 |
| 多篝火气柱叠加（重叠区取最强一柱，非求和） | §3.5 技术裁定 |
| 循环燃烧声、事件 TTS（无环境循环音基建） | R1-15 |
| 怪物/掉落物受气流影响（风托的是翼不是人） | ADR 0017 |
| 乘流话术/教学引导（ItemHint 只写基础说明） | ⭐R2-3（PO 知悉并自担发现风险） |

## 3. 功能规格

> 每块含行为定义 + 验收标准；验收标准是拆票后逐票验收与整体验收的共同口径。
> 涉及 UI 观感处只给行为验收，视觉细节一律以设计定稿（§5）对应节为准。

### 3.1 篝火物品注册

**行为定义**

- 新物品 id **`campfire`**，中文名「篝火」。物品 id 与方块 id 同名族（`block` 字段
  指向燃烧态方块，见 §3.4），零第二层映射。
- 接线必改三件（滑翔翼同款守门三件套）：
  1. **ITEMS 行**（js/items-core.js）：`campfire: {name: '篝火', icon: '🔥',
     block: <B_CAMPFIRE>}`——`block` 字段=放置路由依据（torch 的
     `block: B_TORCH` 同款）；emoji 为 fallback，真图标走 ITEM_PIX（§5 A 分区）。
     无 `dur`（可堆叠消耗品，非可耗损手持光源——灯笼 dur 通道不适用：篝火燃烧
     账在方块侧，不在物品侧）。
  2. **ITEM_HINTS 行**（js/item-hint-registry.js）：基础说明**不剧透乘流玩法**
     （⭐R2-3，PO 改推荐：推荐「话术写乘流教学」被否）。方向口径「暖和的篝火，
     能烧好久好久」（A15/R2-3 意象）；**定稿文案走 UI 通道 D 分区**，红线=全文
     不得出现「飞/上升/气流/翅膀」类剧透字样。
  3. **ITEM_PIX 键**（js/icons.js）：`ITEM_PIX.campfire`（16×16 像素画，§5 A 分区
     定稿后接线）。
- **放置路由（本 spec 裁定，先例引用）**：手持使用=放置——`block` 字段既有语义，
  模式使用链 → PlaceKit.tryPlace（torch/log/bed 同款链路）；**不进
  item-use-registry**（那是穿戴/食用类动作注册表，方块放置从来不在那里，
  js/item-use-registry.js 的 wear 派生先例不适用）。
- 篝火物品不占装备槽、不可食用、无工具语义（isTool/durOf 零参与）。

**验收标准**

- [ ] 背包/快捷栏内篝火卡显示像素图标；点到物品读名称+基础说明（全物品统一通道），
      全文无乘流剧透字样（评审走查）。
- [ ] 手持篝火对实体方块顶面做使用动作=放置（§3.3 细则）；不进 item-use-registry
      （源文本走查：无 campfire 的 use 动作注册）。
- [ ] 三件接线漏一即守门红：item-hint-registry.test（全键⊆ITEMS）、icons-item.test
      （键集=ITEMS）、craft-core.test（配方计数）——`npm test` 可证。

### 3.2 合成配方（图案本 spec 定稿）

**行为定义**

- 材料（R1-12，全部现成零新增）：`stick` 木棍×3 + `log` 原木×3 + `coal`/`charcoal`
  煤炭或木炭×1（任选——候选数组格子规约先例：torch 配方 `[['coal','charcoal']]`
  格子，js/craft-core.js:65-66）。
- 站点：**工作台级 3×3**（`station: 'table'`）；产物：`campfire`×2（消耗品烧完
  就没，一发多给一个补偿——R1-12 拍板理由）。
- **图案（本 spec 设计定稿，MC 正典篝火图案直译——「煤在上、棍成三角、原木垫底」）**：

  ```
  行0:  [stick, [coal|charcoal], stick]    ← 左右斜棍 + 顶部煤心
  行1:  [null,  stick,           null ]    ← 中央立棍（三棍成三角架）
  行2:  [log,   log,             log  ]    ← 三根原木垫底
  ```

  数据行（照 craft-core RECIPES 条目形状，js/craft-core.js:54-66）：

  ```js
  {id: 'campfire', out: {item: 'campfire', n: 2}, station: 'table',
    shape: {rows: [['stick', ['coal', 'charcoal'], 'stick'],
                   [null, 'stick', null],
                   ['log', 'log', 'log']]}},
  ```

  设计理由：①MC 正典篝火配方逐格对应（stick×3+煤/炭×1+log×3 与拍板数量严格一致）；
  ②左右镜像对称（镜像匹配下自身对称，6 岁怎么摆都不吃亏）；③读图自下而上
  「柴堆→架子→火心」与实物结构一致；④煤/炭任选复用候选数组格子，零新规约；
  ⑤cost 由 shapeCost 派生（单一数据源）。
- **公开配方（不进 KIT_HIDDEN_RECIPES）**：纯玩具无任务（⭐R1-13），配方卡常显=
  孩子自由合成入口；隐藏配方需新增解锁谓词机制（现状不存在，glider-spec §3.2
  同论证），本特性不引入。体验馆 hiddenRecipesOpen 全开与本建议正交兼容。
- 计数：每次合成 `craft_campfire` 经 counts 通道按**件数**自动累加（`craft_<物品
  id>`×产量 n 既有机制；本配方 n:2，首次合成即 +2）——本期零任务消费，账照记
  （「只 += 不判断」纪律），为二期（如烤肉/任务）留免费台账。
  （勘误 2026-11-16：原「首次合成」表述未显件数口径、验收行误书 =1，与既有
  advTally 链按件累加不符；施工线 T-C1 红测已按 =2 口径绿，纸面随齐。）

**验收标准**

- [ ] 3×3 工作台按图案合成出篝火×2，材料扣减正确（棍 3/原木 3/煤或炭 1）；镜像
      摆放同样命中；用木炭替换煤炭同样命中。
- [ ] 随身 2×2 摆不出（站点门禁生效）；材料不足时产出槽不亮。
- [ ] craft-core.test 配方计数同步更新；新配方过形状防错网与两两不同构检查
      （craft-core.test.js:135 起/:188 起）。
- [ ] 配方卡在合成列表常显（探险与体验馆双端）；合成产出即入合成卡。
- [ ] 首次合成后 counts.craft_campfire=2（件数口径：既有通用链按
      craft_<物品id>×产量 n 累加，配方 n:2；无任务消费、无报错）。

### 3.3 放置规则（R1-03/R1-04）

**行为定义**

- 底座：**任何实体方块的顶面**（石头/泥土/木头/沙子……不限可燃底座——儿童版少
  一条失败规则）；不可放四类=advPlaceCheck 既有门机械结果，零第二份实现：
  ① 水面（solid:false 当不了支承）② 悬空/侧面依附（篝火无 wall 旗标）
  ③ 非 replaceable 薄块顶（支承块 thin≠null 当不了支承，如引线）④ 两态篝火顶
  （thin:0.5≠null，同门拒绝）。**覆盖成功例外**：replaceable 薄块白名单（花三
  色/草丛/树苗/火把/死灌木七件，config 用户拍板 2026-10-28）点中=覆盖放置成功
  （落点=被点格盖掉旧薄块，既有覆盖机制），不属失败类。
  （勘误 2026-11-16：PO A3 原口径「薄块（火把/花）顶上不可放」中薄块顶部分与
  replaceable 覆盖机械事实冲突——草丛/树苗/火把顶与花顶同为白名单成员、同覆盖
  成功，按「既有机制=权威」原则修订为上述四类机械口径，失败话术适用面（水面/
  悬空/thin 支承拒）不变；**PO 追认：花顶覆盖成功（2026-11-16，与既有
  replaceable 机制一致；经 sm-campfire 提请）**——本项已闭。）
- **本 spec 技术裁定两条**：
  1. **篝火（任一态）自身不可作为篝火底座**——防「火塔叠罗汉」（上半截悬空火
     视觉破碎）；由既有 thin 支承门机械达成（篝火 thin:0.5≠null 当不了支承，
     两态同拒），零特判零显式排除；一条温和话术复用放置失败通道。
     （勘误 2026-11-16：原「对两态 id 显式排除」为实现方式误预测，实为 thin
     支承门机械涵盖；行为验收已按两态顶拒绝+话术+零扣件绿。）
  2. 篝火半格实体（§3.4 物理形态）对**其他**可放置物是否为合法支承，走既有支承
     判据机械结果（勘误 2026-11-16 反向修订）：**篝火顶面不得作支承**——thin
     支承门要求支承块 thin==null，篝火 thin:0.5 两态皆拒（火把等 thin 块顶面/
     wall 侧面同门拒绝）；实体新块（thin==null，如石头）不经支承门，叠篝火上方
     机械成功（床顶同待遇），零特判。
- **放置即燃（R1-04）**：放置成功=燃烧态方块落格 + 侧账建条（满时长，§3.4）+
  点燃音效 1 声（§3.7）——零点燃步骤（无打火石道具，6 岁少一步是一步）。
- 放置失败=温和话术（A3 方向「篝火要放在结实的东西上面哦」；定稿走 UI D 分区）+
  **不扣物品**。
- 路由：PlaceKit.tryPlace（探险/体验馆共享缝，模式使用链入口），不硬编码场景
  分支；onPlaced 后钩挂侧账建条（树苗挂表同缝先例）。

**验收标准**

- [ ] 石头/泥土/木头/沙子顶面放置成功且立即燃烧（侧账=满时长）；实体方块（如
      石头）可叠放两态篝火上方（不经支承门机械成功，床顶同待遇）。
- [ ] 水面/悬空/非 replaceable 薄块顶（如引线）/两态篝火顶放置失败：温和话术
      出现、物品不扣、世界无变化（四类机械口径，见上底座行）。
- [ ] replaceable 薄块（花/草丛/树苗/火把）点中放置=覆盖成功（落点=被点格盖掉
      旧薄块，既有覆盖机制）。
- [ ] 燃烧态与熄灭态篝火顶面均不可再放篝火，亦不得作任何 thin 块的支承（火把
      插不上篝火顶、贴不上侧面，话术同失败通道；thin 支承门机械达成零特判）。
- [ ] 体验馆同口径放置（零场景分支，评审走查）。

### 3.4 生命周期状态机（ADR 0018）

**状态与触发总表**

| 态 | 进入条件 | 行为 | 退出 |
|---|---|---|---|
| 物品 | 合成产出 | 背包可堆叠物品 | 放置成功 |
| **燃烧态** | 放置（即燃）/ 点击重燃 | light 15 光源、冒烟、热气柱（§3.5）、踩上烫（§3.6）、侧账倒计（§4 时钟） | 燃尽→方块消失；水浇→熄灭态；挖掘→回收 |
| **熄灭态** | 水浇 | 不发光、不冒烟、无气流、不烫、**不计时**；可长期保留（直到挖走或重燃） | 点击→燃烧态（满时长重置）；挖掘→回收 |

**行为细则**

- **方块两态数据表示（本 spec 技术裁定）**：两个方块 id——`B_CAMPFIRE`（燃烧态）
  与 `B_CAMPFIRE_OUT`（熄灭态），config BLOCKS 各配 `campfire: 'lit'|'out'` 身份
  旗标；id=**81/82**（定稿建议值；config 现号段已用至 80=B_GATE_SIGN，2026-11-16
  核实——原文「现号段已用至 74」为陈旧事实已更正；两态连号；落位以实现期
  config.js 现状为准）。**对齐「身份判据只读旗标」哲学**（block-lifecycle D1：
  机制跟着「它是什么」走）：浇熄/重燃=方块 id 互换（编辑链一笔账，edits 账本
  天然重放，**熄灭态零侧账**）；备选「单 id+状态旗标侧账」否决——config 旗标是
  静态表，状态进侧账=第二份状态账本+重放对账复杂化，与方块级联身份原则相悖。
- **物理形态（本 spec 技术裁定）**：半格实体块——`thin: 0.5, solid: true`
  （床头 thin:0.55 同款先例）：可碰撞、**可站立**（「踩上烫」与「踩火起飞」的
  前提）、高度半格贴合篝火实物观感；挡光判定零特判（走 light-core mkPolicy
  现行公式，旗标组合机械决定），贴图入集归 UI B 分区（图集 16×16=256 格新格位）。
  （注：碰撞站立与放置支承是两套机制——§3.3 勘误后篝火顶不得作放置支承，但
  可碰撞可站立口径不变：「踩上烫」「踩火起飞」前提不受影响，与床头 thin:0.55
  可站先例同款。）

### 3.5 热气流与乘流（ADR 0017，核心块）

**引擎层可复用机制（PO 点名 spec 硬约束）**

- 新引擎层纯核心 **`js/updraft-core.js`（UpdraftCore）**——气流源注册表+柱查询，
  **不知道「源是什么」**（篝火是第一个注册源；将来风柱/喷泉复用同一注册面，
  不写死篝火）。interface 草案：

  ```js
  UpdraftCore.mkSim(env) → sim
    env = {read(x,y,z)→id, solidOf(id)→bool}   // 依赖全参数注入（fluid-core 装配纪律）
    sim.add({x, y, z, r, h, lift})   // 注册气流源：源格心(x,y,z)+水平半径 r(格)+
                                     // 柱高 h(格)+升速 lift(格/s)
    sim.remove(x, y, z)              // 注销（燃尽/浇熄/挖走时由装配层调）
    sim.query(px, py, pz) → {lift, top} | null
                                     // 最强命中柱（多柱 max 语义非求和）；
                                     // 内嵌遮挡列扫（见下）
    sim.count() / sim.clear()        // 观察口 / 清场（切模式/换图）
  ```

- **模板硬约束（fluid-core 同款纪律，逐条）**：引擎层纯核心·零 THREE·零 DOM·
  同名单测（test/updraft-core.test.js）·零墙钟（核心内无任何时钟推进——纯注册+
  查询无状态步进，比 fluid-core 更纯）·零随机·零全局（read/solidOf 经 env 注入，
  world.js 与单测共用同一装配防两份漂移）；notifyEdit 类编辑挂点不需要（无扩散
  语义——源增删即注册/注销两意图口）。
- 装配：sim 实例归引擎装配面（world.js，与 fluid sim 同装配位）；voxel.js 物理
  经意图缝查询（`setGliderEquipped`/`setFly` 先例：引擎物理读、模式层写注册/
  注销经意图 API）；模式层篝火账本（§3.4/§3.8）在状态迁移点调 add/remove——
  燃烧态=add，燃尽/浇熄/挖走=remove，重燃=add。

**气柱几何与判定（R1-09/R1-10 ⭐——20 格为 PO 改推荐，原推荐 12 被否）**

- 柱：篝火格正上方；水平 **3×3 截面**（判定=玩家水平坐标所在格与源格
  Chebyshev 距离 ≤1，整数格列运算全离散，BotW 调研 §7-1 迁移口径）；自火面
  向上 **20 格**（top = 火面 y + 20）。
- **遮挡截断（本 spec 技术裁定，interview 推荐「遮挡段以上无升力」采纳）**：
  query 时对玩家所在 (x,z) 列自火面+1 向上扫至玩家脚部高度，遇**首个实体方块
  即截断**——该列此高程无升力（屋顶/树冠挡风，物理直觉）。每帧每玩家一次
  ≤20 格列扫，零预计算零维护账。
- **多柱重叠不叠加（本 spec 技术裁定，R1-11+BotW 调研 §7-6 同向）**：query 取
  lift 最强一柱（max 语义；同参数源任一命中即托升），重叠区速度恒为单柱值。

**乘流行为（滑翔翼唯一爬升手段，ADR 0017 例外两处+衔接裁决）**

- **只认翼玩家**：气流查询只在滑翔物理分支与柱内跳跃展翼判定消费，且都要求
  gliderEquipped——无翼玩家、怪物、掉落物零参与（D 案「被动吸升」否决：路过
  篝火不会被动上天）。
- **柱内托升**：滑翔态 & query 命中 → `vel.y = +lift`（替换 GLIDE.sink 缓降；
  出柱即回落缓降——BotW 同口径「出柱推力即止」）。ADR 0016「高度只减不增」
  在柱内暂停执行；例外边界=单一判据「处于活跃气流柱内」，不得外溢。
- **柱内跳跃=立即展翼（R1-09，ADR 0017 门槛豁免）**：柱内跳跃瞬间无视「离地
  >2 格」阈值直接展翼（gliding=true）——站火边一跳就「噗」地升空，一步起飞；
  跳跃初速被升速即刻接管。踩着篝火方块本身起跳同此（3×3 含篝火格）。
- **取消闩锁 × 气流柱（BotW 调研 §7-2 点名衔接点，本 spec 裁决）**：**闩锁优先
  于气流**——闩锁态玩家在柱内按无翼自由下坠（lift 只作用于滑翔态），落地/入水
  清闩锁照旧；柱内空中再点跳跃=解除闩锁+主动展翼（既有语义，glider-spec §3.4）
  → 再获升力。零特判，两契约自然咬合。
- **摔落伤害联动（ADR 0014 口径照抄）**：展翼段不计落差——乘流全程安全；柱顶
  出柱=普通滑翔缓降；柱内主动取消=自收翼点重新累计（气柱顶取消收翼→摔当段
  高度的账，20 格取消≈重伤，孩子自己读出「别在最高点收翅膀」）。
- **贴顶接受边界**：室内（有顶）气柱把滑翔玩家压在天花板下（碰撞清 vel.y、
  下一帧再给 lift 的贴顶抖动，不穿墙）；水平操控可漂出柱——接受，不做特判
  （已知边界登记，评审不得当 bug 报）。

**验收标准**

- [ ] 装备滑翔翼站燃烧篝火旁（3×3 内）跳跃：立即展翼+从火面持续上升至 20 格
      顶（到顶耗时≈20/lift 秒，参数表口径）；出柱瞬间回落缓降（高度只减不增
      契约柱外恢复）。
- [ ] 3×3 判定边缘：柱内一格有升力、柱外一步（Chebyshev 2）无升力；4 格高台
      柱外起跳展翼后飘入柱内=开始上升（进入即乘，BotW 官方口径移植）。
- [ ] 遮挡：篝火正上方放一块石头 → 石头以上全柱无升力（柱内跳跃不再起飞），
      石头与火面之间矮段照常有；树冠部分遮挡=被挡列无升力、未挡列照常。
- [ ] 多柱：两篝火气柱重叠区升速恒为单柱值（不叠加可证：双柱与单柱到顶耗时
      相等）；熄灭任一火后另一柱照常。
- [ ] 无翼玩家在柱内跳跃/行走零气流参与（不展翼不被吸升）；怪物/掉落物入柱
      零位移。
- [ ] 柱内展翼豁免不外溢：柱外平地跳跃永不误展（glider-spec §3.4 回归全过）；
      柱内闩锁态下坠到落地（气流不清闩锁），落地后再跳恢复豁免起飞。
- [ ] 切模式/换图/读档后 sim 清场重建（无幽灵气柱：燃烧篝火数=sim.count()）。

### 3.6 烫伤（ADR 0019）

**行为定义**

- **节拍**：踩上**燃烧态**篝火（onGround 且支撑格=燃烧篝火）**每满 1 秒扣 1 血**
  （节拍 20 刻，岩浆 lavaTick 计息器同款先例：引擎内累积器、离火清零）；
  接触不足 1 秒不满节拍不烫——**踩火起跳起飞天然豁免**（起飞接触 <1s），不设
  特判也不补烫（ADR 0019「有意设计，不得当 bug 修掉」）。
- **通道**：环境伤 advEnvHurt（**不经盔甲折减**，与摔落/岩浆同通道口径）；
  血尽走现有零惩罚死亡流程（'home' 切图满血 / 体验馆 'inPlace' 原地满血）。
- **引擎只报事件**：voxel.js physics 内支撑格采样+计息器，到拍置位
  `worldEvents.fireTick`（新事件，voidFall/splash/land/lavaTick 先例族）；
  玩家扣血结算归模式层（引擎不知 HP）。
- **怪物同规则（R2-2）**：怪物支撑格=燃烧篝火 → 同节拍同伤害，结算归模式层
  怪物更新；烫死走现有死亡/掉落链，**无击杀归属特判**（夜怪围家时门口烧篝火=
  顺手的防御工事玩法——PO 采纳理由）。
- **不烫面**：熄灭态、燃尽后、物品形态、掉落物形态、气柱本身（篝火上方空中）
  一律不烫（ADR 0019 例外只覆盖「生物踩上燃烧中的篝火方块」）。
- 数值 1 血/秒实现期可微调，规则形状（节拍制/环境伤通道/双物种）以 ADR 0019 为准。

**验收标准**

- [ ] 站燃烧篝火 0.9s 跳出：无伤；站 2.1s：扣 2 血（节拍边界可证）；计息器离火
      清零（再次踩上从零起拍）。
- [ ] 踩火跳跃起飞全程不被烫（接触不满节拍）；熄灭态篝火上站立任意时长无伤。
- [ ] 全身钻甲站立：伤害不折减（环境伤口径）；扣至血尽走现有死亡流程零惩罚。
- [ ] 怪物踩火同款掉血；烫死照常掉落、无击杀记账特判；怪物不主动避火（本期
      不加 AI——门口烧火=防御工事玩法成立可证）。
- [ ] 全程零 TTS（无「好烫」类播报——烫伤是安静的环境反馈）。

## 4. 时钟语义独立决策项（scrum-master 点名单独成节）

**问题**：燃尽倒计时（及与之共用节拍的烫伤计息）走什么钟。三个候选时间基：
计划刻游戏钟（独立累积器）/ 昼夜 dayTime / 墙钟。

**拍板案：独立计划刻游戏钟——20tps 累积器、dt 注入、与昼夜 dayTime 解耦。**
（✅ **PO 已拍板**（2026-11-16，经 scrum-master 转达）：采纳推荐案。理由随记：
熔炉/流体泵同拍冻结（暂停语义一致）、整数刻入档零漂移（存→读幂等）、
零墙钟确定性红线。本 spec 全文按拍板案书写。）

机制：篝火账本 `tick(dt)` 挂主循环 gameplay 块（`advFurnace.tick(dt)` 同缝同拍，
adventure.js:5307——菜单/未锁定/暂停即不喂=冻结）；内部 dt 累积器把帧增量量化成
1/20s 整刻（`pumpFluids` 的 fluidAcc 同款累积器先例，world.js:752-761），燃尽余量
与烫伤计息全按整刻记账，余量单位=刻（6000 刻=300s）。

## 6. 实现红线（违反即红）

1. **热气流必须引擎层纯核心**（ADR 0017 PO 点名硬约束）：`updraft-core.js` 零
   THREE·零 DOM·零时钟·零随机·零全局注入（read/solidOf 参数注入，fluid-core
   mkSim 同款装配纪律）；同名单测 test/updraft-core.test.js；篝火只是第一个
   注册源，机制不写死篝火（将来风柱/喷泉复用同一注册面）。
2. **引擎不知道玩法**：updraft-core 只知「气流源」不知篝火；燃尽/浇熄/烫伤结算
   全在模式层；引擎物理消费 query（滑翔分支+跳跃展翼判定），注册/注销经意图
   API（setGliderEquipped/setFly 先例）；voxel.js 若新增顶层绑定，登记玩家段头
   注释白名单（唯一权威）并按 conventions §1.10 评估守门正则。
3. **滑翔物理改动面收在引擎 voxel.js 滑翔分支**（glider-spec §5 红线 1 同款）：
   柱内升速/展翼豁免是引擎行为；模式文件禁直写玩家六绑定
   （conventions.test.js:131-148 执法照常）。
4. **契约例外边界不得外溢**（ADR 0017）：例外只开「柱内垂直速度可为正」+「柱内
   展翼门槛」两处；柱外「高度只减不增」照旧；「只缓降」其余面（匀速/转向/落地
   收翼/取消闩锁/水面软着陆/动作暂停）柱内柱外全部照旧适用——glider-spec §3.4
   回归测试是例外不外溢的验收口径。
5. **放置路由不进 item-use-registry**：`block` 字段既有放置链（模式使用链→
   PlaceKit.tryPlace），torch/log/bed 同款；item-use-registry 只收穿戴/食用类
   动作（wear 派生先例），篝火不得注册进去。
6. **身份判据只读旗标哲学**（block-lifecycle D1）：两态=两个方块 id + config
   `campfire: 'lit'|'out'` 旗标，判据不含位置/模式条件；熄灭态零侧账（状态全在
   方块 id，edits 天然重放）；浇熄/重燃=一笔 id 互换编辑。
7. **档键纪律**：payload 新键 campfires 只记燃烧态（`[[posKey,{left}]]` +

## 8. 术语表（spec 内钉死概念定义；GLOSSARY.md 词条正文含实现细节，待实现完工后由实现线补——glider 先例）

- **篝火（campfire）**：探险模式（+体验馆同口径）可合成消耗品方块道具——放置
  即燃的照明+热气流源。物品 id `campfire`，方块两态 id。⚠️ 与 js/camp-core.js
  （训练营机制 CampCore）名字撞车：语境「训练营」归 CampCore、「篝火」归本特性，
  文档与代码不混称（§6-11）。
- **热气流（上升气流/updraft）**：燃烧中篝火产生的向上气流柱（3×3 截面 × 20 格）；
  引擎层可复用气流机制（updraft-core）的第一个注册源；装备滑翔翼的玩家在柱内
  可被托升（ADR 0017）。
- **气流源（updraft source）**：updraft-core 注册表的一个条目——{格心, 半径,
  柱高, 升速}；引擎不知道源是什么（篝火/将来风柱/喷泉同构）。
- **乘流**：滑翔态玩家处于热气流柱内被托升的行为——滑翔翼唯一爬升手段
  （柱内「高度只减不增」暂停执行）。
- **燃尽**：篝火烧完自然消亡的终局（6000 刻，干净消失无掉落，ADR 0018）。
- **熄灭态**：被水浇熄后的篝火方块形态（不发光/不冒烟/无气流/不烫/不计时；
  点击重燃=满时长重置；可长期保留）。
- **烫伤**：踩上燃烧中篝火的节拍制环境伤（每秒 1 血，玩家+怪物同规则，
  ADR 0019）。
- **篝火账（campfires 侧账）**：世界档 payload 键——燃烧中篝火的余刻账

## 10. BotW 对照附录（调研参数表 vs PO 拍板值；调研全文
[botw-campfire-research.md](botw-campfire-research.md)——五级信源纪律，8 项未验证
如实标注）

| 参数 | BotW 原值（调研口径） | 本项目拍板/初值 | 关系标注 |
|---|---|---|---|
| 燃尽 | **无燃尽机制**——营火永久燃烧（逆工程 FireBurnBase 无时长字段；熄灭=雨/风/坐火） | 300s=6000 刻自然燃尽 | **有意偏离（PO 立项拍板「自然燃尽的消耗品，不照抄 BotW 永久营火」）**；数值锚=灯笼 dur=300s 同档 + 同仓 MC 燃料表煤 80s/块量级参照（调研 §2.2 迁移锚点） |
| 气流触发门槛 | 单火**无**气流；≥4 捆木柴起流/3 捆维持（社区实测，非官方） | **1 座篝火即出完整气流** | **有意简化**（儿童版砍堆柴材料管理负担；调研 §6 建议同向「单篝火=完整功能」） |
| 气柱高度 | 单火崖壁级（数米~十余米，未验证）；串联可达塔级 ≈70m（攻略转述） | **20 格** | **有意偏离（PO 拍板）**——⭐R1-10：推荐 12 被否，「能上山头，飞得更爽」；调研建议 8~12 亦低于拍板 |
| 气柱宽度 | Radius 参数名级（数值未公开）；目测与火堆占地同量级 2~3m | **3×3 截面**（Chebyshev 半径 1） | 对齐体素整数网格（调研 §6 建议同向） |
| 升速 | 未验证（物理分析：净升=风速−下沉 3.2m/s；强流量级估 3~4m/s） | +3.0 格/s 初值（实现期调参） | 量级对齐（净升 > 缓降 0.7 四倍余量） |
| 点燃 | 木柴+打火石二段交互（打火石一次性消耗） | **放置即燃**（零点燃步骤） | **有意简化**（无打火石道具；调研 §6 建议同向「省掉二段交互与失败挫败」） |
| 多火叠加 | 纵向串联接力（updraft over updraft）、多捆=更强单柱 | **不叠加**（max 语义） | **有意简化**（调研 §7-6 建议同向：就近取最强、物理稳定省判定） |
| 熄灭 | 雨/强风/坐火熄灭，熄后可原样重燃 | 水浇熄灭（无天气系统），点击重燃 | 机制移植换触发源；「熄后可重燃」口径一致 |
| 烟/气流表现 | 灰白烟柱=远距信号；白色旋涡粒子=气流可读性语言（定性） | 方向采纳（观感规格 C 分区定稿中） | 视觉语言移植（非数值拷贝） |
| 照明 | 营火发光（连续光照，无数值口径） | light 15 | 锚换 MC 正典（火把 14/灯块 15 先例族） |
