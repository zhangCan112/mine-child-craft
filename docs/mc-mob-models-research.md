## 2. 模型语言通则（geo.json 怎么读）

**单位**：全部尺寸以「模型像素」为单位，**1px = 1/16 方块 = 0.0625 格**。标准人形总高 32px = 2.0 格
（碰撞箱 1.95/1.9 是另一套口径，本项目 MOB_TYPES.h 已映射）。

**骨架（bone）** = 动画枢轴组：`pivot` 是旋转原点（px 坐标），`parent` 成树，`neverRender` 的骨头
（如 waist）纯当挂载点。**立方体（cube）** = `origin`（角点，x 向左负、y 向上、z 向前负——**脸朝 −Z**）
+ `size` [宽,高,深] + `uv` [u,v]（该盒六面在贴图上的展开锚点）+ 可选：

- `inflate`：六面向外膨胀（第二层皮肤 0.25 / 羊毛 1.75 / 高压苦力怕 2.0）——**官方的 overlay 惯例**；
- `mirror`：左右肢体共用一份 UV 镜像（官方左右臂/腿大量使用）；
- `rotation`（cube 级）与 `bind_pose_rotation`（bone 级）：四足身体**竖着建模再绕 X 转 90° 躺平**
  （cow/pig/sheep/ravager 全族如此；chicken v1.12 改用 cube 级 rotation）；
- `locators` / `*Item` 骨头：挂物点（rightItem pivot ≈ [−6,15,1]），玩家/猪灵/卫道士均备。

**贴图**：每怪一张 UV 图，尺寸随体量：常规 64×32（老版人形）或 64×64（玩家/猪灵/灾厄村民）、
大怪 128×64~128×128（疣猪兽/铁傀儡/监守者/劫掠兽）、末影龙 256×256、恼鬼 32×32。
**脸部五官几乎全部画在贴图上**（8×8×8 头的正面），真正立体的脸部部件只有少数：
村民/女巫/铁傀儡鼻（2×4×2 / 2×4×2 / 2×4×2）、猪灵吻部、疣猪兽獠牙、劫掠兽角、鸡喙/肉冠、牛角。

**动画语言**（humanoid.animation.json 原文数据）：

- 走路 `animation.humanoid.move`：**腿摆幅 = 臂摆幅 × 1.4**，左右反相，余弦驱动
  （`leftleg: tcos0*1.4 · leftarm: tcos0 · rightarm/rightleg 取负`）；
- 待机 `bob`：双臂 z 轴轻浮 ±2.865°（cos(life_time×103.2)）；
- 攻击 `attack.rotations`：右臂下劈正弦包络 + 身体同向微转 11.46°；
- 头部 `look_at_target`：头骨 pitch/yaw 直接跟视线（无 IK）；
- 潜行 `sneaking`：双臂前举 72°、腿前后错位；骑乘 `riding.legs`：双腿 −81° 弯折。

**变体 = 基座骨架 × scale + 换贴图 + 少量追加骨**（wiki 数值）：
凋灵骷髅 = 骷髅 ×1.2、洞穴蜘蛛 = 蜘蛛 ×0.7、远古守卫者 = 守卫者 ×~2、尸壳/溺尸/流浪者/沼骸 =
僵尸/骷髅换贴图（溺尸加了 jacket/sleeve/pants 三层 inflate 0.5 overlay + hat inflate 1.0）。
**MC 自己就是「共享基座骨架 + 逐怪文件」的组织方式**——每怪一个 `.geo.json` + 一张贴图，
这与本项目拍板的「一怪一文件 + 基类生成器」方向天然对齐。

  「不够我的世界」的最大单一来源即在此：改为 12/12/8px 等比即跃升。附属件（帽/背包/发）可保留为
  本项目自绘皮肤的一部分（官方帽层 inflate 0.5 就是干这个的位置）。

## 4. 基座骨架族（官方的「基类」）

**人形（zombie，64×32）**：头 8×8×8（pivot y24）+ 身 8×12×4（y12..24）+ 双臂 4×12×4
（pivot [±5,22,0]，垂到 y12）+ 双腿 4×12×4（pivot [±1.9,12,0]）。
→ 僵尸/尸壳/溺尸/僵尸猪灵/玩家共用；溺尸加三层 inflate 0.5 外套；僵尸猪灵同形换皮。
**本项目 hum() 已接近**（差在臂 0.2→0.25、腿 0.24→0.25、眼/嘴应从盒子改贴图）。

**细骨人形（skeleton）**：同人形但**四肢 2×12×2**（臂 pivot [±5,22,0]、腿 pivot [±2,12,0]）。
→ 骷髅/流浪者/沼骸/凋灵骷髅（×1.2）。

**灾厄村民基座（vindicator/pillager，64×64）**：人形变体——头 **8×10×8**（更高）+ 鼻 2×4×2 前突 +
身 8×12×**6**（更厚）+ 长袍 overlay inflate 0.5（8×18×6）+ **交叉双臂盒**（arms 骨：两条 4×8×4 斜搭一条 8×4×4）
+ 正常双臂 4×12×4 备攻击姿态。卫道士/掠夺者/唤魔者/女巫同基座（女巫加四级歪帽+鼻，见 §5）。

**四足（cow 型）**：身 N×18×10 竖建模绕 X 转 90° + 头（带角/鼻，pivot 在颈）+ 四腿 4×12×4。
→ 牛/猪（腿 4×6×4）/羊（毛 overlay inflate 1.75）/疣猪兽（大身 16×14×26 + 耳/獠牙）/劫掠兽（巨型变体）。
鸡是独立小四足（身 6×8×6 转 90°、腿 3×5×3、带翼 1×4×6）。

**虫形（spider 型）**：头 8×8×8 前置（−Z）+ 前体 6×6×6 + 腹 10×8×12 + **8 条 16×2×2 水平长腿**
（pivot [±4,9,z]，腿是横着的细杆，动画绕枢轴摆）。蠹虫/末影螨 = 分节链（见 §5）。

## 6. 与现状的三个结构性结论

1. **比例已七成接近，脸全靠贴图**：人形/四足基座的盒子尺寸项目大多在 ±10% 内；真正「不像」的
   一是玩家 Q 版比例（§3），二是**所有脸都用小盒子拼**——官方脸 95% 画在贴图上。上贴图（Q4 拍板）
   后 MOB_RIG 里大量 eye/mouth 盒子可删，rig 反而变简单。
2. **官方第二层语言（inflate overlay）是重要观感源**：外套/袖/帽层（0.25）、羊毛（1.75）、高压苦力怕（2.0）、
   溺尸外套（0.5）。顶点色方案表达不了「外壳层」，贴图方案应把 inflate 列为 DSL 一等字段。
3. **官方组织方式 = 「共享基座 + 逐怪文件」**：husk/stray 这类变体的 geo.json 与基座逐字相同、只换贴图；
   差异怪在基座上加骨（耳/鼻/帽/獠牙）。这正是拍板 Q1「一怪一文件+基类」的官方同构物——
   基类=基座骨架（人形/细骨/灾厄/四足/虫形），每怪文件=「基座引用 + 追加骨 + 贴图 + scale/变体参数」。

## 7. 落地建议（对齐 Q1~Q6 拍板）

1. **DSL 采用 MC 像素单位**（Q5）：cube 用 `{origin|size}`（px）或换算后的世界尺寸常量（1px=0.0625），
   bone 用 `{pivot, axis, parent}`——官方数据可直填，本笔记即验收对照表。
2. **rig DSL 一等字段**：`size/origin/uv/inflate/mirror` + `pivot` 骨骼树；渲染侧 (type×bone) 合批不变，
   材质从共享顶点色改为**每怪一张 16/32/64px 程序贴图**（延续贴图图集/像素图标工坊的自绘管线惯例）。
3. **一怪一文件**（Q1）：`js/mobs/<type>.js` 声明 `{base: 'humanoid'|'skeleton'|'illager'|'quad'|'spider'…,
   bones: 追加/覆写, tex: 自绘贴图, scale, armStyle…}`；基座生成器 = §4 的五种官方基座；
   玩家（Q3/Q6）= 同一 DSL 的 humanoid 消费者 + Avatar 私有壳（手持物/装备动画/头部俯仰/相机显隐保留）。
4. **先打样后铺开**（Q6）：第一批 = 玩家 + 僵尸 + 苦力怕 + 骷髅 + 蜘蛛 + 羊（覆盖 5 基座 + overlay + 换皮变体），
   验收「同框截图对比」后按族铺完 42 怪。
5. **尺寸验收表**：§5 每怪的 px 尺寸即测试基准（对齐 ±10% 内通过），变体怪按 scale 折算。
