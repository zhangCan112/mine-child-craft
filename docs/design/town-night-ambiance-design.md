## 0. 一页速览

- **一句话**：既有 11 柱暖点连成「进镇归家路」，窗光=有人家、塔灯=地标醒着——把「小镇亮着灯等你来」（entry-transition §B.3）在镇内兑成完整一句话。
- **新增光源点 3-5 个**：民居窗光 2-4 扇（两栋民居各 1-2 扇）＋钟塔灯 1；**既有 11 柱灯罩完形零新增光源**（灯块芯原位保留，只增暖金灯罩造型笔）。
- **夜灯补的是「生活感/归家感」，不是「安全感」**——镇夜安全感已由无怪门禁＋恒 calm＋禁焦虑链成立（§1 诊断），措辞红线：本文任何表述不得暗示镇夜全黑或存在安全感缺口。
- **公共裁决四条**（§3）：夜端点维持月光蓝折线零引擎缝零另呈 / 门控=clockPhase 四段渐变窗设计意见（机制归工程票）/ 零逐帧动态灯性能护栏 / 安全叙事底线全项继承。
- **工程票要点清单**（§5）：调色板灯罩键、belfry 夜态增补、门控机制票、灯罩造型笔、窗光/塔灯落位——供需求线立票引用，本文不落 prefab-specs。

### 诊断结论：「安全但素」——素不在黑，在读法

中间态实测=**月光蓝穹 + 环境光残量 + 零星烘焙暖点 + 无怪 + 恒 calm**。把 #7 摊开看，夜镇的读法其实是：**「路灯亮着、店里亮着、家里黑着、塔上黑着」**——一个没人住的空村。安全感已由 #5/#6 + 禁焦虑链（town-entry-transition-visual-spec §A.6）成立，**夜灯要补的不是安全感，是生活感与归家感**：

- **窗光=有人家**：两栋民居窗（玻璃 id 18，全透光——GLOSSARY 光照核心词条差异 #7）夜里透出的是室内暗色，读法「屋里没人」；
- **塔灯=地标活着**：钟塔夜态灯火默认不做（town-prefab-specs §4.1），home 侧剪影已有「塔灯 1」，镇内正主反而黑着；
- **珠串=路活着**：11 根灯柱暖点已存在但无读法组织，白天「交叉口灯柱轻提示」（town-map-design §4.3 · buildings §6.2）的引导语言到夜里断了线。

以上三类正是 home 侧剪影灯点读法 **「小镇亮着灯等你来」**（town-entry-transition-visual-spec §B.3）承诺的镇内兑现面——孩子在 home 东带看见的「亮着灯的镇」，进镇之后夜里应该还是同一句话。案②定稿围绕这一承诺展开，PO 拍板接受的中间态（ADR-0017 P2）是定稿的底座，不是被否定的现状。

## 3. 公共裁决（四条，逐字成文）

### a. 夜端点天色=维持（本线裁决，ADR-0017 决策 5 授权）

**裁决：月光蓝折线零改动、零引擎缝、零另呈项。**

- **评注**：夜端点 `#0a1430` 深夜蓝 × 地面暖灯点的**冷暖对比**正是「暖夜」的配方——暖从地平起，天是月光蓝，灯是 `#FFD89A` 暖光，层次天然分明；若把天穹也暖化，地面灯点反而失去对比、画面发闷。维持夜端点是本案观感的地基，不是妥协。
- 「黄昏橙不做」是既定差异 #16（js/daylight-core.js:88-90 注释），不重开。
- **另呈项结论：无**——本线对「是否需要夜端点暖化缝」的裁决=不需要，无注册替代案，[ADR-0017](../adr/0017-town-day-cycle-unfreeze.md) 决策 5 预留的另呈通道本次不动用。

### b. 氛围门控=设计意见（机制归工程票，何时亮=模式政策）

**明确边界**：门控机制（怎么实现渐变）归工程票；「何时亮」是模式政策（setPlayerGlow 政策缝先例——js/world.js:371「政策『何时亮』归模式层」）。本节只给设计意见：

- **亮灯窗=clockPhase 四段锚点**（零新枚举、零新魔法数，断点=DIM_KEYS 12040/13670/22330/23961，js/daylight-core.js:30/:128-135；ADR-0017 决策 4 先例）：
  - **dusk 段（12040→13670，≈82 秒渐暗窗）**：随天暗渐亮——灯跟着天一起暗下去，孩子读到的因果是「天黑了，灯亮了」，不是「灯突然出现」；
  - **dawn 段（22330→23961，≈82 秒渐亮窗）**：随天亮渐熄——对称收束，晨光接管。
- **禁瞬亮瞬灭**：§A.6 惊吓闪禁项（快闪/频闪/爆闪）直接覆盖灯光开关场景（entry-transition-visual-spec §A.6）；两窗各 ≈82 秒、同拍 applyDaylight 50 tick 量化节拍（≈2.5 s 一阶、无感阶进，js/world.js:173-179）——云朵亮度手动跟同一折线（js/world.js:189-191）就是「Basic 类亮度按 50 tick 键写值」的现成先例。
- **载体分野**（设计意见附注，供工程票分路径）：烘焙灯块类点（现状灯柱/店灯/挂灯同族）**零门控需求**——白天日光通道主导、暖点读作造型，夜里自然显为灯火，现状灯柱已在示范；自发光面片类（§2.2 载体 B）才需要 dusk/dawn 渐变窗。理由重申：dayTime tick 裸常量散写消费方=昼夜核心 _Avoid_ 明文（GLOSSARY「昼夜核心」：「把折线/窗口判据散写回消费方」）。

### c. 性能护栏=零逐帧动态灯

- **夜灯全部走烘焙/自发光类**：光照核心方块光烘顶点 aBlock（灯块 `light:15`，GLOSSARY 光照核心词条）+ 自发光 Basic 材质观感面（云朵/风车叶片「仓库零灯光」先例，js/adventure-dims-core.js:565-566）——两条路都是**零逐帧成本**类；玻璃全透光=窗光可透（GLOSSARY 光照核心词条差异 #7）。
- **不新增逐帧 PointLight**：setPlayerGlow（方块侧 uGlowPos 顶点衰减 + 实体侧单通道 PointLight，js/world.js:371-382）是既有单通道先例，**不作夜灯扩充理由**。
- **低核档同观感**：低核分档面=DPR≤1.5 + VIEW 环收紧 + LPM 守卫 + HUD 1Hz renderer.info 观测（ipad5-performance-design §0 表/§1/§4），**没有动态光源预算行**——本设计把夜灯整体压在零逐帧成本类，低核档不需要新增任何分档参数。
- **验收观测**：可借 HUD 1Hz renderer.info 行（draw calls/triangles）取夜档相对日档的基线差作走查证据（ipad5-performance-design §1 HUD 行）；自发光面片若增 mesh，数面=个位数。
- **密度上限**：§2.1 清单写死（灯柱零新增、新增光源点 3-5、总暖点 ≤18）；全镇口径=buildings §6.3 既定「低密度」+ 节庆点缀面积 <15%（buildings §6.3 第三行）。

### d. 安全叙事底线（进公共验收线，定稿全继承）
