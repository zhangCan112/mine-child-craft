# Spec · 体验馆（showroom）— dev-only 调试模式

- 状态：`ready-for-agent`
- 日期：2026-10-25 · 共识出自 grill 会话（13 问全落），设计论证见 docs/showroom-design.md
- 术语：GLOSSARY「体验馆」（_Avoid_: 实验室——已废弃名）

## Problem Statement（问题）

随着游戏内容越做越多（物品、怪物、武器、道具、烧炼……），每验证一个新东西或
修一个 bug，都要进正式模式跑图、挖矿、凑材料才能摸到被测对象——复现成本高到
开发者常常跳过验证，bug 就漏到后面。需要一个"一切触手可及"的场景：做出来的
东西放进来，亲手玩一遍，bug 自己冒出来。

## Solution（方案）

**体验馆**：仅开发人员可见的调试模式。它是真游戏场景，只是去掉了跑图与挖掘
——平地空场、预置被测道具（v1：熔炉）、背包 27 槽预装全套材料。入口藏在
URL 开发参数里（`?dev=1`），孩子与家长在任何情况下看不到任何入口痕迹。
v1 展品是熔炉：走近点击开面板、投料烧炼、自动放料、退炉回包——烧炼逻辑复用
探险模式的同源纯函数，体验馆里复现的烧炼 bug 就是探险里的 bug。

## User Stories（用户故事）

1. 作为开发人员，我想用 `?dev=1` 打开主菜单时看到体验馆卡，这样不用翻文件就能进调试场景。
2. 作为开发人员，我想不带开发参数打开游戏时体验馆完全不可见（无卡、无页、无任何可点路径），这样孩子永远碰不到开发向入口。
3. 作为开发人员，我想弱网/慢加载下体验馆卡也从不闪现，这样"隐藏"是构造性保证而非运气。
4. 作为开发人员，我想进场就站在预置熔炉旁（4 格解锁圈内），这样零走动立刻开测。
5. 作为开发人员，我想背包 27 槽预装烧炼全原料（铁矿/金矿/原木/圆石/沙/黏土球/四种生肉）、代表燃料（煤/木板/木棍）与各产物对照样，这样不跑图不挖矿直接开烧。
6. 作为开发人员，我想用数字键/滚轮/点选切换快捷栏，这样与正式模式完全同款手感。
7. 作为开发人员，我想走近熔炉点击打开熔炉面板，这样测的是探险同款交互（4 格门槛）。
8. 作为开发人员，我想面板三槽+进度条+燃料余量条实时刷新，这样能发现显示层 bug。
9. 作为开发人员，我想用面板"自动放入"一键把矿石与最省燃料入炉，这样能测自动放料策略。
10. 作为开发人员，我想烧炼按真实速率（2.5s/件）计时出锭、产物槽被异 id 占满时停炉待取，这样边界口径与探险完全一致。
11. 作为开发人员，我想无热无料时炉子暂停、进度与热值保留（不白烧不清零），这样能复现断档续烧边界。
12. 作为开发人员，我想退出体验馆时炉内三笔（待烧料/燃料/产物）全额退回背包，这样零损耗结束一次测试。
13. 作为开发人员，我想 HUD 显示坐标与 FPS，这样 bug 报告能带上现场数据。
14. 作为开发人员，我想加测试材料时只改体验馆顶部一张数据表（一行=一种材料），这样不碰任何逻辑。
15. 作为开发人员，我想体验馆不计儿童时限、不占训练营每日额度，这样调试多久都不吃孩子的账。
16. 作为开发人员，我想体验馆不读不写任何存档键（含共享背包），这样调试永不污染真实进度（尊重 ADR 0002：共享背包唯一存档键由背包壳持有，体验馆自建内存实例、不经背包壳）。
17. 作为开发人员，我想炉态纯内存、退出即清，这样每次进场都是干净初始态、测试可重复。
18. 作为开发人员，我想移动/视角/触屏按钮与正式模式同款，这样配合强制触屏预览（`?touch=1`）能复现触屏端问题。
19. 作为开发人员，我想烧炼状态机直接复用探险核心的纯函数，这样体验馆不是"另一只炉"。
20. 作为维护者，我想 dev 可见性由模式注册表单一权威派生（卡的身份类/CSS 默认隐藏/解锁开关全是派生产物且有断言守门），这样再加 dev 向模式不会手滑漏藏。
21. 作为维护者，我想以后加第二个 dev 模式只需注册表一行+一张卡，这样 CSS/主循环/测试零改动。
22. 作为维护者，我想体验馆脚本的加载序被 boot 冒烟守护，这样共享词法环境的顶层重名立刻红。
23. 作为孩子/家长（反向），我打开游戏永远只看到五个游玩模式与两个训练营，这样儿童界面零开发噪音。

## Implementation Decisions（实现决策）

- **形态**：模式注册表新增一行 `{id:'showroom', name:'体验馆', gated:false, page:false, dev:true, mood:'none'}`——不进儿童时限（与两训练营同类）、无菜单页（卡点击直进，训练营同款先例由主循环通用接线天然支持）。
- **dev 可见性（新小约定，走"注册表+测试断言"升格路径）**：注册表 `dev:true` 字段是唯一权威；卡在主菜单容器内带身份类（派生）、样式表默认隐藏该类、主循环读 `?dev=1`（强制触屏预览 `?touch=1` 同款防御式读取惯例）给 body 加解锁类。三层各司其职：HTML 声明身份、CSS 拥有默认隐藏（构造性防闪现）、JS 只做解锁。
- **烧炼复用**：炉状态机/退炉/近距判定直接调探险核心（AdventureCore）的纯函数族（advSmeltStep/advFurnaceRefund/advNearStation）；面板用模式面板 kit（ModeKit）的熔炉纯显示面板——setSlots/setProgress/setFuel 喂显、"自动放入"只出 plan、实际扣加由模式层经背包核心（InventoryCore）执行。探险的炉与体验馆的炉是同一缝上的两个 adapter，不造第二份烧炼实现。
- **背包**：背包核心 mkInventory 内存实例 + 顶部材料数据表（行形状 `{id, n}`，材料 id 必须在物品核心注册）。不用背包壳、不碰共享背包存档。
- **装场**：场景装填（loadScene）+ SceneKit 平地草场，中心预置熔炉方块，出生点落在解锁圈内；进场装场、退出清场（世界清场归主循环 switchMode 统一）。
- **壳**：模式面板 kit 的 mkMode 标准模式壳；HUD 尾行坐标+FPS（坦克演习场先例）。
- **数据隔离红线**：模式文件内零 localStorage、零任何存档键字面量。
- **操控**：与探险同 UX，不接指针锁定——无需在规范偏离登记表新增条目。
- **先例登记**：这是"模式消费另一模式纯核心"的第一案（体验馆→探险核心）；探险核心本就是零渲染零 DOM 的应用层纯核心，结构上干净。
- **升级触发器（显式）**：若熔炉接线与探险的镜像超约 80 行、或炉行为改动需要两处同步，立即开票抽共享熔炉 kit（届时接口由两个真实消费者共同塑形）。

## Testing Decisions（测试决策）

好测试只测外显行为（注册表派生产物、模式公共接口），不测实现细节——内部重构
后测试必须存活。四条缝全部复用现有缝，不新建：

1. **模式注册表缝**（mode-registry.test 既有模式）：注册表纯数据 ↔ 主菜单 HTML/样式表派生产物的字符串断言。扩展：dev 行的卡在场且带身份类、样式表含默认隐藏规则、解锁类规则在场；`gated:false` 清单更新为三员；游玩模式五员清单断言不变（既有断言自动守"不进儿童时限"）。
2. **模式契约缝**（adventure-mode.test 既有先例，新镜像文件）：模式文件可 require、注册行形状断言、主循环 MODES 表接线正则、**数据隔离键扫**（无 localStorage/存档键字面量——声音清单注册表测试扫全库字面量的同款手法）、材料数据表全 id ∈ 物品核心。
3. **boot 冒烟缝**（零改动自动覆盖）：新模式脚本入列即被守护——加载序、顶层重名、共享词法环境炸错。
4. **探险核心纯函数缝**（既有单测）：烧炼单步/退炉已有测试；体验馆复用不重写、不重复测。

## Out of Scope（范围外）

- 挖掘/放置（v1 不接；接线很薄，需要时说一声）
- 全方块/全怪物陈列（v2 展陈方向；第一个展品类型只有熔炉，不建"展品框架"——一个 adapter 的缝是假缝，第二个展品类型出现时再塑形）
- 任意发物品面板（v2；材料数据表先顶着）
- 共享熔炉 kit 抽取（触发器制，见实现决策）
- 指针锁定/扩展键盘操控（用到才接，接了登记偏离）
- 炉态持久化（永不——体验馆每次进场都是干净初始态）
- 自动化测试管线（体验馆是开发者亲手玩的调试台，不是 e2e 框架）
