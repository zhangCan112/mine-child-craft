# 生态恢复机制 · 设计稿

> 起因（2026-10-28 用户需求）：「消耗掉的资源包含生态和矿产，需要缓慢恢复，但绝不能把已建好的建筑恢复掉。」
> 调研依据：[minecraft-eco-recovery-research.md](minecraft-eco-recovery-research.md)（下称「调研稿」，MC Java 正典逐条取证）。
> 用户拍板（2026-10-28，ADR 0006 登记）：① 动物走**繁育续场**（幼崽持续出现→慢慢长大→长大前不受伤害），不是凭空重生；树木同理（幼树→长成）；② 时间尺度**混合**——树分钟级当次可见、矿**跨天**回填；③ 矿位回填**全覆盖**（主矿带/坑壁/洞壁/固定彩蛋钻）。
> 关联：既有「随机刻不移植」决策（[block-lifecycle-research.md](block-lifecycle-research.md) §1/§4）继续有效——本机制全部走模式层计时器与日期账本。

## 0. 设计立场（对齐调研稿 §8 三层安全不变量）

MC 保证「自然生长永不毁建筑」靠三层制度，本设计逐层对齐：

| MC 不变量（调研稿 §8） | 本作对应 |
| --- | --- |
| ① 身份白名单：随机刻只作用于注册方块，石头/建筑「抽中也无操作」 | 恢复判据只认**位置账本里的资源位**（树位清单/矿位清单），从不在世界内扫描扩散——玩家放的任何方块不在账本里，天然免疫 |
| ② 拒绝式生长：执行前逐格可替换检查，被挡即放弃 | 树位到期先过「占位预检」，任何一格被非可替换方块挡住就**整株放弃**、重挂计时再等（宁可不长，绝不穿墙） |
| ③ 正典无自动再生（树不长回、矿不再生） | 本设计**刻意扩展**正典：树/矿自主恢复是玩法拍板（儿童零枯竭），安全语义全盘照抄 ①② 与插件三件套（调研稿 §10：位置记录+白名单+基底检查） |

## 1. 通道 A：树位自主恢复（分钟级，当次可见）

- **位清单**：复用 `advTreeSpots()`（确定性树位唯一权威，零世界读）——恢复的「白名单」与建场同源，永不含玩家建筑位。本期只覆盖 home 图橡树林（~40 棵）；松林候选清单未独立成纯函数、远征图无此清单，登记附录 B 不做。
- **凋零判定**：进场重扫（`advRescanSaplings` 同拍同法）——树位基格不是原木 ⇒ 该位「已凋零」，挂恢复计时（`SceneKit.rand(x,z,salt)` 派生 180±60s 抖动，错峰长出）。计时 Map 不落盘、重进重建（树苗既有惯例）。
- **到期执行**（拒绝式，调研稿 §2.2 语义）：
  1. 基格已是原木 ⇒ 位上已有树（孩子自己补种赢了）⇒ **撤销计时**（终局，不再重试）；
  2. 占位预检不过（见下）⇒ **放弃本次**，重挂 90s 后再试——孩子拆掉占位建筑后树会回来（MC 受阻树苗无限重试同语义）；
  3. 预检通过 ⇒ 走既有 `advGrowTree` 全链（`SceneKit.tree` + `advGrowMark` 足迹记账 + 网格收口 + toast）。
- **占位预检 `advTreeSpotOpen`**（纯函数，read 注入）：脚下格必须是草地/泥土（树苗放置同款基底判据）＋ 树盒 `y..y+7 / ±2`（与 `advGrowMark` 同盒）内每格为空气或 `replaceable` 薄块（草丛/花/树苗——MC `#replaceable_by_trees` 思路，树可长过草丛）。盒内出现石头/木板等一切实体方块 ⇒ 不通过。
- **切图隔离**：计时随 `advSaplings.clear()` 同拍清空（防旧图坐标在新图长树——串档事故同款防线）。
- **记账红线**：恢复写入全走 `advGrowMark` 幂等足迹——重放序 = 建场种树 → 砍树 edits → 恢复 edits，逐格同值幂等，确定性重放不破。

## 2. 通道 B：牧场繁育（幼崽续场，用户拍板①）

MC 正典：动物不消失、几乎不自然补员，**繁殖是唯一恢复主通道**（调研稿 §6）；本设计照抄其种群模型，触发力按拍板改为**自动**（见附录 B 差异 4）。

- **自动繁育**：`advHerdTick` 内每帧扫描——同种类两只**成年**动物水平距离 ≤4 格、彼此都不在繁殖冷却、当前图活畜总数 < 上限 ⇒ 中点产幼崽；双亲进入 5 分钟冷却（MC 6000 刻 1:1，调研稿 §6.2）。保留 MC「冷却 + 上限」双闸门防指数爆炸（调研稿 §11.12）；上限 16 = 初始 10 + 繁育余量 6（MC creature 上限 10 锚点，儿童放宽）。
- **幼崽**：出生即 `scaleTo(0.55)`（MC 幼崽约半体型）；当次进场内 10 分钟长成（MC 24000 刻=20 分钟，砍半对齐 20 分钟日限内可见——附录 B 差异 5）；跨天则直接成年。长成 `scaleTo(1)` 并保持一切成年行为。
- **幼崽保护（用户拍板：长大前不受伤害）**：近战/箭矢经 combat-kit `skip` 缝把幼崽**排除出目标选择**（挥击落空=点击自然落到挖掘/放置，箭矢直接穿过），TNT 波及跳过——静默保护：不掉血、不掉落、不进账、无击退。MC 幼崽可被伤害——永久偏差，附录 B 差异 6（零惩罚哲学）。
- **存活记账（世界档 v2）**：死畜账从「索引数组」升级为按图两栏：
  - `dead`：初始 10 只的死畜索引（既有语义不变，初始清单可推导，存档最小）；
  - `bred`：繁育动物清单 `[{k: 怪物键, b: 日期串}]`（繁育体不占初始索引；被杀 = 从清单移除）。
  - 解码归一：`number[]` 老档 → `{dead, bred: []}`；更老 `{dead:[...]}` 单账 → home 桶（既有 P2 归一保留）。形状判据纯函数 `advLivestockNormBucket` 入核心、可单测。
  - 重进播种：初始清单跳过 dead ＋ bred 清单逐条 `isAdult(b, today)` 决定成年/幼崽形态（幼崽重挂 10 分钟计时——计时不落盘惯例）。

## 3. 通道 C：矿位跨天回填（用户拍板②③）

正典矿物永不再生（调研稿 §7/§8.3）；本通道照抄插件三件套（调研稿 §10）：**位置记录 + 类型白名单 + 基底检查**，并按拍板把「定时」换成「跨天」。

- **位清单（白名单）**：建场期记录——`advOreCluster`/`advBuildPit` 矿化/`advTryOre` 洞壁/固定钻四处布点统一收口 `advOreSpot(x,y,z,id)`（记录 + `setBlockRaw`），得确定性矿位清单（同 seed 同清单）；运行期内存持有、每次进场重建，零存档成本。清单只含四矿 id，从机制上排除「回填到别处」。
- **开采记账**：所有破坏路径的 mark sink（级联账本 + TNT 波及两处，`r.id`/`id` 在手）——移除的是矿石方块 ⇒ 世界档新键 `oreRegen["<场景键>:x,y,z"] = 当日`（场景键用 `advSceneKey()` 既有口径，炉键同法）。**当日不回填**（跨天拍板）。
- **回填时机**：进场重放 edits 之后（当前场景的账才结，远征图进图时再结自己的）——遍历本场景到期项（`日期 < 今日`，`budgetDateStr` 唯一拼装点）：
  1. 该格仍是空气 ⇒ 回填原矿种（`setBlockRaw` + `advMarkEdit` + 网格收口），销账；
  2. 该格被占了（孩子把矿坑填了/盖了）⇒ **销账不回填**——玩家改建永久优先于恢复（插件「只覆盖自己标记位」的我们版：只认空气位）。
  - 有回填则一次性 toast「矿山慢慢长回来了一些」。
- **记账红线**：回填 edits 走 `advMarkEdit`——重放序 = 建场 → 开采 edits → 回填 edits，与通道 A 同构，确定性重放不破。任务计数「只增不减」口径天然兼容（回填矿再挖照常计数）。
