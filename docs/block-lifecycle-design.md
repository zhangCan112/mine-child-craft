## 0. 问题定义与改动面盘点

### 根因一句话

体素世界是**纯静态**的：方块只在玩家编辑瞬间变化，编辑之后没有任何「世界自洽」机制——
砍掉树干后，上方的原木与树叶（数据上）永远悬空。这不是某处代码写错，而是移植 MC 逐块
破坏时**漏掉了它的伴生状态机制**（树叶衰减/依附脱落，研究稿 §2）。

### 目标不变量（世界完整性）

> **任意编辑序列之后：没有失撑的树叶（4 格内无原木）、没有悬空的依附块（thin 族）、
> 没有未接地的原木结构（fell 族）。**

判定依据只有方块身份旗标（P2 身份原则）：石头/泥土/圆石……没有旗标，所以在哪挖都不塌；
原木/树叶/thin 族有旗标，所以是树就倒（生成的、种的、孩子自己搭的，一视同仁）。

### 改动面

| 改动 | 文件 | 性质 |
| --- | --- | --- |
| 新纯核心（级联结算） | js/cascade-core.js（新）+ test/cascade-core.test.js（新） | 引擎层·纯核心（§1.2 后缀语义，必有同名单测） |
| 身份旗标 | js/config.js：BLOCKS[5] 补 `fell`、BLOCKS[7] 补 `need`（thin 族旗标现成复用） | 数据，只增不改 |

| 模式消费 | js/modes/adventure.js（掉落/记账/任务/树苗计时）、js/modes/build.js（buildEdits 记账） | 补全（见 D4；arena/tank 零改动） |

复用 rollBlockDrop）；蓄力链/耐久/tier 门禁（craft-core 零改动）；任务表 QUESTS（q1 目标 3 原木
不变，整树掉 5~6 根只是更快达成）。

## D1 · 数据旗标：身份即白名单

```js
/* config.js（只增不改，soft 旗标先例同款赋值式） */
Object.assign(BLOCKS[5], {fell: true});            // 原木：连锁砍倒成员（接地判定见 D2）
Object.assign(BLOCKS[7], {need: {id: 5, dist: 4}}); // 树叶：taxicab 4 内存在原木则存活（P4，BE 口径）
/* thin 族（草丛 40 / 麦 42~45 / 火把 48 / 树苗 50）旗标现成：thin != null 即「依附正下方实心面」，
   破坏侧规则直接复用，不加新字段 */
```

- 语义：`fell`＝结构身份（连成一体、共享接地）；`need`＝伴生身份（依赖某种方块在距离内）；
  `thin`＝依附身份（已存在的放置侧规则，本设计补上破坏侧）。
- **白名单反向断言**（test/blocks-fields.test.js）：全部地形采集方块
  （1 草地/2 泥土/3 石头/4 圆石/8 沙/9 红砖/13 石砖/14 苔石/18 玻璃/36~39 四矿/41 耕地/
  46 工作台/47 熔炉/49 黏土）**不得携带 fell/need**——手滑给石头加旗标即红，这就是
  「地下挖掘不塌」的身份原则防线（位置从未进入判据，无需位置测试）。
- 二期沙子重力再加 `fall: true`（8 号），本期不加。

## D2 · cascade-core 纯核心：三条规则 + 定点迭代

新文件 `js/cascade-core.js`，引擎层纯核心：零 THREE·零 DOM·零 config 依赖（策略经注入，
与 craft-core 的 breakTime 收纯数据 blockDef 同款哲学）。interface：

```js
/* 级联结算：调用方已把触发格清成空气（read 已反映），核心从触发格出发定点迭代，
   通过注入的 write 落地级联移除，返回级联移除清单（不含触发格，触发格调用方自理）。
   policy 从 BLOCKS 派生（world.js 装配）：isFell(id) / isThin(id) / needOf(id) / isSupport(id) */
function cascadeRemove(read, write, x, y, z, oldId, policy) /* → [{x, y, z, id}] */
```

定点迭代（队列元素为 `{x, y, z, oldId}`——刚被清成空气的格）：

```
① thin 脱落：c 正上方是 thin 块 → 支承重查(底座=正下方; wall 旗标薄块(火把)额外
   认四水平实心邻, 墙火把) → 全无则移除并入队（火把/树苗/草丛随底座脱落；
   柱状链式：脱落的 thin 上方若还有 thin 继续脱，天然由队列完成）。
   ①b 贴墙重查：c 四水平邻的 wall 薄块同样重查——支承墙被挖即落；
   地面火把墙边挖底座 → 贴墙还在 → 转依存活(取向从邻块派生, 附录 B)
② fell 接地：c 正上方是 fell 块 → 从它出发 BFS 6-连通穿 fell 块得组件；
   组件存活 ⇔ 存在成员 [y===0（世界底兜底）或 正下方为 isSupport（非空气、solid!==false、非 fell）]。
   不存活 → 整组件移除并入队。组件检查不做缓存：同组件可能先后失去两处支撑
  （双柱桥逐柱炸），每次支撑丢失都重查，正确性优先。
③ need 存活：仅当 c.oldId 是某 need 规则的依赖方块（原木）——树叶存活只取决于
   原木距离，移除树叶/其它方块不改变任何树叶的判定（该性质同时保证手掰单叶
   不误伤装饰叶团，研究稿 §4.5）：
   对 c 的 taxicab ≤ need.dist 盒内每个带 need 规则的方块 L，
   若 L 的 taxicab ≤ L.need.dist 内不存在任何 need.id 方块 → 移除 L 并入队。
⑤ fell 树桩连带（三期 P15）：被移除的是 fell 块且正下方仍是同柱 fell（残余树桩）→
   下方同柱连续段整段移除并入队。与接地无关——树桩本就接地，连带的是「同柱结构
   被斩断」事件本身；桥面等横向结构脚下非同柱 fell，不受牵连（砍桥面中格两半
   各自经柱接地，桥不倒）。
```

终止性：被移除/空出的格才入队（空格天然免疫；树桩连带可与组件移除重复入队同格，
各规则幂等无害）；规则只做移除/下移、总量有界；③ 的再触发是空操作
（树叶移除不改变原木分布）。**放置/生成永不触发**（只有 id→0 且 oldId≠0 进入级联）——
建造模式的悬空装饰（含故意搭的浮空叶团/浮空原木雕塑）只要不发生邻近破坏就永不动。
既有浮空不追认（只在扰动时结算）——三期 P14 起探险 init 以世界卫生清扫一次性治愈
（D9），其余模式维持不追认。

行为速查（全部是同一套规则的推论，无特判）：

| 场景 | 结果 |
| --- | --- |
| 砍树底原木 | 上方整棵树（原木组件+叶团）倒，无树桩 |
| 砍树干中段/顶节 | 上段倒 + 下方同柱树桩连带倒（P15）——整树消失，不残留撑冠树桩 |
| 挖树底下的泥土 | 树失去接地 → 整树倒（P5） |
| 双柱桥砍/炸掉一柱 | 另一柱仍接地 → 桥存活；两柱全失 → 整体倒 |
| 砍双柱桥桥面中格 | 两半各自经柱接地 → 桥存活（树桩连带只认同柱，不横向蔓延） |
| 孩子搭的原木柱/原木房 | 与自然树同一规则（身份原则）——砍柱脚即倒；砍中/顶段=同柱下方连带倒（P15，材料全掉落零损失） |
| 贴脸双树砍其一 | 邻树叶团 4 内仍有自己的原木 → 存活（P4 取 4 的意义） |
| 石头/泥土结构（含地下隧道） | 无旗标 → 永不级联 |
| 挖火把/树苗/草丛的底座 | 脱落并按各自掉落表掉落（树苗顺带撤 20s 计时，模式层） |
| TNT 炸进林区 | 圈内块照旧逐块结算；波及原木则整树级联倒（掉落走默认表，不进任务，P6） |

成本：单棵树 ≈ 5 原木 + ~49 树叶，BFS+区域扫描千格级读——与现有 TNT 半径 3.5（~179 格
逐块）同量级，一次性的、不进每帧路径。

## D3 · world.js 接线：唯一 choke point

```js
/* world.js 内部（editBlock 与 editBlockDirty 共用；级联期间 write=setBlockRaw 裸写，
   脏记账收敛到最后一次 markDirty×N + flushDirty 一次——编辑管线语义不变） */
const CASCADE_POLICY = {/* 从 BLOCKS 派生 isFell/isThin/needOf/isSupport，装配期一次 */};
function applyCascade(x, y, z, oldId) {
  const removed = cascadeRemove(getBlock, setBlockRaw, x, y, z, oldId, CASCADE_POLICY);
  for (const r of removed) markDirty(r.x, r.z);
  return removed;
}
/* editBlock：破坏时返回 [{x,y,z,id}...]（触发块碎屑照旧；级联块合并发一次加量碎屑），
   放置返回 []；既有调用方忽略返回值则行为不变（级联自动生效）——向后兼容 */
/* editBlockDirty：同款返回（tank.js:494 注入链零改动即得级联） */
```

全模式破坏路径已逐一核实收敛于此（研究稿 §3 表）：探险挖掘/探险 TNT/建造/竞技场 →
editBlock；坦克炮击 → editBlockDirty。**任何新的破坏路径必须走这两入口**——这条既有纪律
随级联能力升格为硬约束（漏走 = 级联不生效 = 世界不变量破洞，world-integrity 测试兜底）。

## D4 · 模式层消费（引擎报清单，模式定政策）

引擎只报「哪些方块被级联移除了」；掉落/记账/话术是玩法政策，留在模式层：

- **探险** `advBreakBlock`：对返回清单逐块 `advMarkEdit`（存档一致性，D5）+ 默认表掉落
  （rollBlockDrop 不传工具——级联是「砸倒」不是「剪」）+ 任务计数按玩家亲手挖同口径
  （蓄力链触发的级联记 mine，TNT 链的不记，P6）+ 树苗计时清理 + TTS「哇！大树倒啦！」。
- **探险** `advExplode`：循环内逐块 editBlock 的返回值同款消费（级联块掉落默认表、不进任务）。
- **建造** `onMouse`：`const removed = editBlock(x,y,z,0)` 后逐块 `buildEdits[...].set(key, 0)`
  ——**不补记账则重进后砍掉的树复活半截**（触发块没编辑、级联块没编辑，正是本次 bug 的
  存档版）。竞技场/坦克零改动（场景每局重建，无记账无掉落）。

## D5 · 存档一致性（正确性红线）

级联是引擎对世界的**多块修改**，各模式的差异日志必须完整覆盖：探险 `advEdits`、建造
`buildEdits` 均逐块记录（D4）。回归锚点测试：砍树 → 存档 → 重进（确定性重建 + edits 重放）
→ 断言整树不复活。漏记任何一级联块，重进就会出现「半棵幽灵树」——比原 bug 更隐蔽，
故此测试为一期必交付。

## D6 · 观感与反馈（一期口径，P8）

触发块碎屑照旧（editBlock 内置）；级联块合并为**一次加量碎屑**（树冠中心）+ 掉落雨
（~17 个掉落实体：5 原木 + 概率掷出的树苗/苹果/木棍，drops.js 真空拾取 ≤2.5 格自动收）
+ `sfx('hit')` + 探险话术。倾倒刚体动画/逐块阶梯消失（30ms/块）列二期——跨帧级联会
把数据/存档时序复杂化，一期一次性结算。

## D7 · 沙子重力（二期）：fall 旗标 · 移动语义 · 规则④

```js
/* config.js（D1 旗标家族新增一员，身份原则不变） */
Object.assign(BLOCKS[8], {fall: true}); // 沙子: 重力方块(失去支撑整体下沉, MC 口径)
```

- **移动语义**：级联清单条目从「移除 `{x,y,z,id}`」扩展为可选 `to`——带 `to:{x,y,z}` 的
  条目是**移动**（原格清空、落格得方块，方块存活故**不掉落、不进任务**）；消费方记账
  必须记**两格**（原格 0 + 落格 id），漏记任意一格重进即错位。
- **规则④（fall 重力）**：处理一个空格 c 时，正上方是 fall 块 → 该列**连续 fall 段**整体
  下沉——落点自段底向下扫，穿空气/水（非支撑即穿），途遇 thin 先弹出（P10 砸碎），直到
  世界底或实心支撑；整段下移 Δ，段顶空出的原位入队（上方依附块弹出/原木结构失接地
  连锁倒——与规则②无缝衔接）。同列隔空的既有浮空段不追认（与浮空原木同口径：
  只在扰动时结算）。
- **放置触发（P9，本期唯一新增的触发面）**：`editBlock` 放置 fall 旗标方块且脚下非支撑
  → 即时下沉（`cascadePlace` 入口，复用规则④的落点扫描）。原木/树叶/thin 放置仍零触发。
- **数据/动画解耦（P12）**：数据级即时结算（确定性重放与存档红线不变）；视觉走
  `Fx.fallBlock`（1×1×1 色块自原位坠至落位，重力加速度+着地淡出，逐块 40ms 阶梯），
  纯 overlay 不承载语义，上限 24 块超出静默。editBlockDirty（坦克批量）不放动画
  （远场景自带爆风观感）。

## D8 · 倒树观感（二期）：落块雨（P13）

砍倒触发时，级联清单里 fell 旗标的条目（原木）逐节调 `Fx.fallBlock` 自原位坠到
`groundTop(x,z)+1`（树倒后地形顶），60ms/节阶梯；树叶维持一期聚合碎屑。与掉落雨
（物品真空飞行）叠加成「树散架→原木滚落→材料飞进背包」的三拍反馈。刚体倾倒动画
**明确不做**（跨帧数据/存档时序复杂化，收益不成比例，附录 B 登记）。

## D9 · 世界卫生清扫（三期）：旧档浮空一次性治愈（P14）

级联只由编辑触发（D2「放置/生成永不触发」+「既有浮空不追认」）——级联上线**之前**的
存档里，已被砍去树干/支撑的浮空块（孤儿冠、悬浮树、浮沙、悬空依附块）永远无人结算，
孩子看到的就是「修了还浮」（2026-10-24 判别实验：模拟旧档重放，砍整干档重进后 238
片孤儿叶、砍底节档 5 棵整树悬浮）。P14 拍板：探险 init 在确定性重建 + edits 重放之后、
`advRescanSaplings` 之前（被治愈掀掉的悬空树苗不再重挂计时）做一次全图治愈。

- **纯核心** `cascadeSweep(read, write, policy, w, h, d)`（cascade-core，与
  cascadeRemove 同清单契约，移动条目带 to）：全图扫四类违例并播种——孤儿 need 块
  直接移除（依赖早已不在，破坏触发面永无时机）；未接地 fell 组件整组件移除（成员
  入队后规则③照常重查伴生块——**邻树互保的叶按 P4 口径存活**）；悬空 fall 段/悬空
  thin 以脚下合成空格入队，交规则④/①按既有语义下沉/脱落（砸碎沿途 thin/穿水等
  连锁照常）。违例判据与 test/world-integrity.test.js 的全图不变量扫描同构。
- **不动点迭代**：一轮治愈可能揭出新违例（多由队列链当场结算，扫描兜底斜邻等
  漏网），扫到无违例止。终止性：每轮净移除或净下移至少一格（take 减块数、settle
  降重心不增块），总量有界；干净世界首轮即空 → 返回 `[]`。
- **接线**：world.js `applySweep()`（同 applyCascade 装配 + 脏记账，移动条目两格）；
  **仅探险 init 消费**（重放后调用，静默记录 edits——移动条目两格记账与
  advCascadeApply 同口径）。建造模式不调：故意搭的浮空装饰（叶团/原木雕塑）保护
  口径不变。
- **存档一致性（D5 红线延伸）**：治愈逐块记 edits，落盘后重进无违例 → 清扫为空
  操作（幂等，不会每进一次世界重复清扫/重复记账——红线测试锁定）。
- **静默口径**：装场期迁移不是游戏事件——无掉落（当年砍树时掉落已领，凭空生成
  物品反而鼓励反复进出刷材料）、无话术、无任务计数。
- **成本**：全图 128×128×48 ≈ 78.6 万格一次扫描（旗标查表前置 + 列主序复用下方
  格 id）+ 违例局部结算；浏览器同 realm 实测同款逻辑 ~5-10ms，装场期一次性，
  不进每帧路径。
