## 一、方向甲：「奶油曲奇按钮」（保守打磨派——同暖纸盘，纯质感精修）

### 1.1 定位

**一句话**：骨架和色盘一根手指都不动，把「黄纸片」精修成「奶油曲奇+实体按键」——受光、厚度、弹性三件事做足。
**现状丑在**：平（无光无厚度）、脏（94% 半透明互渗）、呆（瞬现无入场）。
**本方向靠什么可爱**：纸面有受光渐变（上亮下暖）、构件有实体厚度（按键吃进底面的实色边）、入场有真动画（上滑+轻弹，回归 §5.4 既有口径——现状反而是违规瞬现）。**零新资产、零 DOM 结构改动、零 spec 增补需求**，全部值落在既有口径区间内，是三方向里唯一「拍板即可施工、无需动权威」的选项。

### 1.5 六岁可读性论证

- **字号下限**：body 18 / ghost 18 / chip-label 18 / speaker 20，全部 ≥18 加粗圆润——修正 #6 后**无一处低于 §4.4 线**。
- **文字对比度自核**（WCAG 相对亮度粗算，ink `#5A4636` L≈0.075）：
  - ink on 渐变最深档 `#F7DFAD`（L≈0.74）：**≈6.3:1** ✓（AA 4.5 大幅过）
  - ink on chip 金渐变深档 `#E8B23C`（L≈0.50）：**≈4.4:1**，18px bold 属大字（≥14pt bold），AA 大字线 3:1 **✓**（厚度边 #B9822A 不承载文字）
  - ink on ghost 柔白底：≥7:1 ✓
- **触屏热区**：chip 64×64 触点（热区=触点 64 ≥56 ✓）；ghost min 44×44 ✓；相邻 chip gap 16 ✓；speaker/praise/装饰均不可点，无热区义务。
- **上半屏 ≥55%**：甲方向不增任何布局尺寸（渐变/阴影/keyframes 全部零占位变化）✓。

### 1.6 方向甲自评（权衡如实）

- **最大权衡**：保守=可爱度上限有限。骨架还是「一块底部卡片」，PO 若要的是「焕然一新的萌」，甲可能只是「从 60 分修到 80 分」。
- **最不确定**：金 chip 厚度边（按键隐喻）在「对话选择」语境是否成立——它更像「确认键」语言；若 PO 觉得硬，可退化为纯软影（1.4 表内单点可调，不影响其余）。

## 二、方向乙：「毛边绘本对话泡」（换骨架派——面板气泡化，一套气泡语法）

### 2.1 定位

**一句话**：把「屏幕底部一块板」改成「村民嘴里长出来的大对话泡」——panel 气泡化（超大不对称圆角+尾尖指向）、chip 泡豆化、speaker 名牌骑缝，三件套从「三个无关盒子」变成**一套气泡语法**（大泡带小泡，World Bubble 与 Session Panel 同族）。
**现状丑在**：panel 是无语境的几何卡；与 World Bubble 毫无血缘，说话人、气泡、选项各说各话。
**本方向靠什么可爱**：漫画/绘本是 6 岁最熟悉的视觉母语——「泡=有人在说话」无需教学；毛边不对称圆角自带手绘温度；名牌骑缝让「谁在说」第一眼可见。零新资产、**零 DOM 结构改动**（尾尖/骑缝/毛边全部 CSS 伪元素可达）。

### 2.5 六岁可读性论证

- **字号**：同公共修正（body/ghost 18、chip-label 18、speaker 20）✓；豆内 label 横排后豆宽自适应（`min-width:64px; padding:8px 16px`），3 字标签豆宽 ≈128px，3 豆+2 gap16 ≈ 416px < panel 宽 360px 下限？**超了**——处理：窄窗（panel 360px 档）label 落 icon 下方（`flex-direction:column`，豆收窄到 96px，3 豆 ≈320px ✓）；宽窗横排。响应式断点写在规格内不留临场发挥。
- **对比度**：ink on 奶油白 `#FFF9EC`（L≈0.93）：**≈7.9:1** ✓ 全场最佳；豆上 ink：on `#FFD89A`（L≈0.75）≈6.4:1 ✓ / on `#9AD6E2`（L≈0.66）≈5.6:1 ✓ / on `#9BCF7A`（L≈0.56）≈4.8:1 ✓（三豆全部过 AA 正文线，无需借大字豁免）。
- **热区**：豆触点 min 64×64（热区同 ≥56 ✓）；pill 拉宽只增不减 ✓；ghost 44 ✓；gap 16 ✓；名牌不可点无热区义务。
- **上半屏 ≥55%**：名牌骑缝 absolute 不占高；尾尖伪元素不占位；panel 内容高与现状同构 ✓。

### 2.6 方向乙自评（权衡如实）

- **最大权衡**：尾尖是**静态指向下方**——说话人 NPC 可能出现在画面中上任意位，尾尖永远朝下只是「大致朝向说话人一侧」的绘本式示意，不是精确投影（逐帧投影=JS 改动，超纯视觉边界）。PO 若要求精确指向，需追加小改动票（town-ui.js 尾尖朝向写入，类比 bubble 的 is-anchored 既有机制，成本可控但要动装配层）。
- **最不确定**：白泡会不会「太白」——镇全局是暖黄光，纯白泡可能显冷。缓解：奶油白 `#FFF9EC` 本身带暖头（非 #FFFFFF），且暖纸名牌压住泡顶补暖；实屏走查仍建议看 30-dialog-live 机位再定。

## 三、方向丙：「果冻甜品屋」（换盘强可爱派——暖纸×樱粉双盘，甜品质感）

### 3.1 定位

**一句话**：整套会话 UI=甜品屋——泡芙面板（奶油白底+樱粉双皮）、马卡龙选项豆（双色夹心圆饼）、糖珠表扬徽章；**樱粉 #F2C2D9（B_PINK_WOOL，revamp-spec §2 镇景公共件色）首次入 UI 大面**，与镇内樱粉树冠/布幔/旗同源呼应。
**现状丑在**：单一暖黄盘从头糊到尾，无第二色支撑层次；方正硬朗与 6 岁甜味审美错位。
**本方向靠什么可爱**：马卡龙夹心、圆饼豆、彩色软影（暖粉调）三件甜品语言全上；「暖纸×樱粉」双盘编织——暖纸保底防腻，樱粉提可爱度上限。这是三方向里**对 PO「观感自然度>省成本」偏好赌注最大**的一个：赌的是「樱粉大面=和樱花镇景融为一体」而非「粉=幼幼化出戏」。零新资产、零 DOM。

### 3.6 方向丙自评（权衡如实）

- **最大权衡**：樱粉大面是口味赌注——成则「甜品屋和樱花镇是一家人」，败则「幼幼化出戏」；且彩影+双皮+马卡龙的实现细节最多（仍是纯 CSS，但视觉验收样张需求最高）。
- **最不确定**：暖粉调软影在暖黄世界光下的实际观感（粉影可能被世界色染脏）——需实屏 walk 机位验证，本提案给的是纸面推演值。
