### 诊断结论：「安全但素」——素不在黑，在读法

中间态实测=**月光蓝穹 + 环境光残量 + 零星烘焙暖点 + 无怪 + 恒 calm**。把 #7 摊开看，夜镇的读法其实是：**「路灯亮着、店里亮着、家里黑着、塔上黑着」**——一个没人住的空村。安全感已由 #5/#6 + 禁焦虑链（town-entry-transition-visual-spec §A.6）成立，**夜灯要补的不是安全感，是生活感与归家感**：

- **窗光=有人家**：两栋民居窗（玻璃 id 18，全透光——GLOSSARY 光照核心词条差异 #7）夜里透出的是室内暗色，读法「屋里没人」；
- **塔灯=地标活着**：钟塔夜态灯火默认不做（town-prefab-specs §4.1），home 侧剪影已有「塔灯 1」，镇内正主反而黑着；
- **珠串=路活着**：11 根灯柱暖点已存在但无读法组织，白天「交叉口灯柱轻提示」（town-map-design §4.3 · buildings §6.2）的引导语言到夜里断了线。

以上三类正是 home 侧剪影灯点读法 **「小镇亮着灯等你来」**（town-entry-transition-visual-spec §B.3）承诺的镇内兑现面——孩子在 home 东带看见的「亮着灯的镇」，进镇之后夜里应该还是同一句话。本提案三案全部围绕这一承诺展开，PO 拍板接受的中间态（ADR-0017 P2）是三案共同的底座，不是被否定的现状。

## 一、公共裁决（三案共享，逐条带依据）

### a. ②夜端点天色=维持（本线裁决，ADR-0017 决策 5 授权）

**裁决：月光蓝折线零改动、零引擎缝、零另呈项。**

- **评注**：夜端点 `#0a1430` 深夜蓝 × 地面暖灯点的**冷暖对比**正是「暖夜」的配方——暖从地平起，天是月光蓝，灯是 `#FFD89A` 暖光，层次天然分明；若把天穹也暖化，地面灯点反而失去对比、画面发闷。维持夜端点是三案观感的地基，不是妥协。
- 「黄昏橙不做」是既定差异 #16（js/daylight-core.js:88-90 注释），不重开。
- **另呈项结论：无**——本线对「是否需要夜端点暖化缝」的裁决=不需要，无注册替代案，ADR-0017 决策 5 预留的另呈通道本次不动用。

### b. ③氛围门控=设计意见（机制归工程票，何时亮=模式政策）

**明确边界**：门控机制（怎么实现渐变）归工程票；「何时亮」是模式政策（setPlayerGlow 政策缝先例——js/world.js:371「政策『何时亮』归模式层」）。本节只给设计意见：

- **亮灯窗=clockPhase 四段锚点**（零新枚举、零新魔法数，断点=DIM_KEYS 12040/13670/22330/23961，js/daylight-core.js:30/:128-135；ADR-0017 决策 4 先例）：
  - **dusk 段（12040→13670，≈82 秒渐暗窗）**：随天暗渐亮——灯跟着天一起暗下去，孩子读到的因果是「天黑了，灯亮了」，不是「灯突然出现」；
  - **dawn 段（22330→23961，≈82 秒渐亮窗）**：随天亮渐熄——对称收束，晨光接管。
- **禁瞬亮瞬灭**：§A.6 惊吓闪禁项（快闪/频闪/爆闪）直接覆盖灯光开关场景；两窗各 ≈82 秒、同拍 applyDaylight 50 tick 量化节拍（≈2.5 s 一阶、无感阶进，js/world.js:173-179）——云朵亮度手动跟同一折线（js/world.js:189-191）就是「Basic 类亮度按 50 tick 键写值」的现成先例。
- **载体分野**（设计意见附注，供工程票分路径）：烘焙灯块类点（现状灯柱/店灯/挂灯同族）**零门控需求**——白天日光通道主导、暖点读作造型，夜里自然显为灯火，现状灯柱已在示范；自发光面片类（§二 件语言基座载体 B）才需要 dusk/dawn 渐变窗。理由重申：dayTime tick 裸常量散写消费方=昼夜核心 _Avoid_ 明文（GLOSSARY「昼夜核心」：「把折线/窗口判据散写回消费方」）。

### c. ④性能护栏=零逐帧动态灯

- **夜灯全部走烘焙/自发光类**：光照核心方块光烘顶点 aBlock（灯块 `light:15`，GLOSSARY 光照核心词条）+ 自发光 Basic 材质观感面（云朵/风车叶片「仓库零灯光」先例，js/adventure-dims-core.js:565-566）——两条路都是**零逐帧成本**类；玻璃全透光=窗光可透（GLOSSARY 光照核心词条差异 #7）。
- **不新增逐帧 PointLight**：setPlayerGlow（方块侧 uGlowPos 顶点衰减 + 实体侧单通道 PointLight，js/world.js:371-382）是既有单通道先例，**不作夜灯扩充理由**。
- **低核档同观感**：低核分档面=DPR≤1.5 + VIEW 环收紧 + LPM 守卫 + HUD 1Hz renderer.info 观测（docs/ipad5-performance-design.md §0 表/§1/§4），**没有动态光源预算行**——本设计把夜灯整体压在零逐帧成本类，低核档不需要新增任何分档参数。
- **验收观测**：可借 HUD 1Hz renderer.info 行（draw calls/triangles）取夜档相对日档的基线差作走查证据（ipad5-performance-design §1 HUD 行）；自发光面片若增 mesh，数面=个位数。
- **密度上限逐案写死**（见 §二各案），全镇口径=buildings §6.3 既定「低密度」+ 节庆点缀面积 <15%（buildings §6.3 第三行）。

### d. 安全叙事底线（进公共验收线，三案全继承）

「镇=安全的地方」儿童叙事优先（ADR-0017 决策 3 引 GLOSSARY 口径）；夜间观感靠光照/氛围（P3 拍板口径）。三案无论选谁，以下全部成立、零触碰：

| # | 底线 | 依据 |

| 1 | 镇内恒无怪（维度门禁零牵动，纯视觉方案不触碰任何门禁/实体面） | town-map-design §6.3.4 · ADR-0017 决策 3 / P3 |
| 2 | 恒 calm 曲，不换曲 | ADR-0017 P4（维度行 mood 锁） |

### 2.2 案①「窗光星点」（极简增暖）

**一句话定位**：只补「家里有人、塔还醒着」两层情感锚点——最小施工面让夜镇从「空村路灯」翻成「亮灯人家」。

| 字段 | 内容 |
|---|---|
| 光源件清单 | 窗光：民居 A（cottage-gable）×1 栋 ×1-2 扇 + 民居 B（house-loft）×1 栋 ×1-2 扇 = **2-4 扇**（每栋 1-2 扇口径；点位避让门窗开合与花坛，坐标细读归施工票）；钟塔灯：钟室暖点 **1** |
| 密度口径 | 全镇新增发光点 **3-5 个**；现状烘焙点（灯柱 11+店灯+挂灯）零改动——总暖点 ≤18 |
| 叙事读法 | 「村里有住户，钟塔还醒着」——home 侧「窗灯 3+塔灯 1」剪影的镇内同构最小呼应 |
| **比中间态多什么、为什么值得** | 中间态缺的两块情感面（窗黑=没人、塔黑=地标睡着）一次补齐；3-5 个点换「空村→人家」的读法翻转，性价比全场最高——孩子夜里逛镇第一眼有了「这是有人生活的地方」的着落 |
| 施工面量级 | **S**（3-5 点位，建场增笔或 Basic 面片；钟塔灯需 prefab-specs §4.1 夜态增补一行登记） |
| 风险与回退 | 灯块芯窗光若实屏过亮（BFS 溢光）→ 降为每栋 1 扇；钟室灯点若喧钟 → 降档为檐下弱光面。回退=逐点摘除，点位级独立、零耦合 |

### 2.3 案②「灯火归家」（推荐）

**一句话定位**：案①全量 + 街灯读法完形——既有 11 柱暖点连成「进镇归家路」，把「小镇亮着灯等你来」在镇内兑成完整一句话。

| 字段 | 内容 |
|---|---|
| 光源件清单 | ①案全部（窗光 2-4 扇+钟塔灯 1）**＋街灯完形**：既有 11 根灯柱（灯块芯已烘焙发光）增**暖金灯罩造型笔**（`#E3B23C`，buildings §4.1 既定用途；灯罩=造型增笔非新光源——灯块原位保留）；**零新增光源点**，路径读法定稿=门廊 2（gate-w/gate-e，spawn 第一眼）→ 广场及环 5（含广场中心 lamp-plaza）→ 北路 1 → 断头驿 3（消解「断头扎草地」） |
| 密度口径 | 灯柱零新增（11 现册）；窗光同案①；全镇光源点 ≤18 不变，造型件 +11 |
| 叙事读法 | 「**亮着灯等你来**」镇内兑现：白天灯柱是造型提示（buildings §6.3），夜里是引路的珠串——从 spawn 门廊一路亮到广场与三条路尽头；窗光=村民在家，与 T-NPC-13 c2 日程「天黑=村民回家」互文（ADR-0017 决策 4 工程动机的视觉面：孩子看见天黑+窗亮，因果可读） |
| **比中间态多什么、为什么值得** | 中间态的暖点是散珠，本案给串珠的线：①生活感（案①）+②夜间动线可读（白天引导语言的夜态延续，夜里逛镇不迷路——对 6 岁玩家是真实的归家安全感**体验**，与「无威胁」安全感正交）+③「灯罩完形」让灯柱白天档造型更贴 buildings §6.3 语言（白天观感微变=暖金冠形，方向是加分非破坏） |

| 风险与回退 | 灯罩若几何包死灯块会吞光——设计约束写死：**罩形不包顶**（立柱框/悬挑环，灯块顶面与四侧保留出光面），施工票几何自查项；白天档罩形观感走查把关。回退=摘罩回灯块裸头（现状），案①部分独立可回 |

### 2.4 案③「暖夜满灯」（最 full）

**一句话定位**：案②全量 + 节庆层——广场灯笼/摊位暖点+窗光密度上浮，夜=「赶完集的暖夜，家家亮着灯」。

| 字段 | 内容 |
|---|---|

## 三、选型指引（PO 向，一页）

### 3.1 三案对照

| 维度 | 案① 窗光星点 | 案② 灯火归家（推荐） | 案③ 暖夜满灯 |
|---|---|---|---|
| **一句话** | 窗光+塔灯：空村→人家 | 案①+街灯珠串：亮着灯等你来 | 案②+灯笼节庆层：赶完集的暖夜 |
| **观感差异（对中间态）** | 补情感锚点（家/塔） | +夜间动线可读、灯柱造型完形 | +广场人气与节庆余温 |
| **新增光源点** | 3-5 | 3-5（+造型笔 11，零新光源） | ≤14（总暖点 ≤28） |
| **施工面** | **S** | **M−** | **M-L** |
| **新登记项** | belfry 夜态增补 1 行 | +调色板灯罩键登记 | +灯笼件 prefab-specs 夜态登记、挂点避让核查 |
| **主要风险** | 窗光溢亮（可降档） | 灯罩吞光（几何约束写死可防） | 灯过密/挂点耦合（分层回退可防） |
| **回退** | 逐点摘除 | 摘罩回裸头；案①独立回 | 分层回退（摘灯笼层=案②） |
| **推荐理由** | 预算最紧时的保底项 | **三案里唯一同时兑现「归家感+动线+互文」的档位**：面量 M− 可控、把 home 侧「亮着灯等你来」的承诺在镇内说完整、与 c2 日程「天黑=村民回家」构成可读因果；回退分层干净 | 夜叙事最热闹，但点位/登记/避让成本三案最高——适合 PO 要「节庆感」优先时选 |

**推荐倾向**：案②。理由如上表——它用一档 M− 的面量把「窗光=有人家、街灯=路活着、塔灯=地标醒着」三层读法一次说齐，且与既有人力面（c2 日程）互文最紧。**倾向仅供 PO 参考，裁决归 PO。**
