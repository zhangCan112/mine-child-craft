## 3. 接口形状

### 3.1 数据表 TOWN_NPC_ANCHORS（14 行纯数据）

```js
{
  id: 'npc:v01',            // id 空间：npc: 前缀（镜像 task: 先例，与 TOWN_MAP.anchors 导览锚零碰撞）
  npcId: 'V01',             // 回指注册表 id（跨表对账在测试侧桥接）
  waypoints: [ { x: 79, y: 24, z: 94, face: 'south' } ], // 单航点=静态站位；多航点=巡逻环
  note: '广场南入口面南迎客',
}
```

- 10 条村民静态站位（V01~V10）+ 3 条动物站位（A01~A03）+ G01 巡逻环（4 航点闭环，villagers 设计 §5.3「沿广场-主要路径慢巡逻」；日程化到站/傍晚钟塔停驻等**语义注释进 note，不建多时段数据**——日程行为归未来行为层票）。合计 14 行 = 13 单航点 + G01 四航点。（勘误 2026-11-14 reviewer 两轴评审观察：原文「11 条静态+3 条动物+G01」加总 15≠14,实现按 §4.8 字面 14 键口径落,无缺口。）
- face ∈ 上/北/南/东/西 朝向词表（与 TOWN_MAP.anchors face 字段同词表）。

### 3.2 纯函数 anchorOf(id, legIndex)

```js
anchorOf('npc:v01')                       // 静态锚恒返 waypoints[0]
anchorOf('npc:g01', 2)                    // 巡逻锚返 waypoints[2 % n]（取数器，不做时间推进）
// → { x, y, z, face }（快照拷贝，外部改写不反渗）
```

- 零墙钟零随机：`legIndex` 由装配层注入（谁推进它=行为层日程，归波次二/未来票）；未知 id 抛拼写域错（镜像 townInteractRegistry 口径）。
- **航点量化裁决落地点**：锚点只在到站（legIndex 变化）时跳变，不随移动插值——本函数天然就是这个语义（README §3.3）。

## 4. 验收标准（红绿可测）

1. **贴地**：全部 waypoint `y === TOWN_MAP.core.groundY`（24）。
2. **可达域**：全部站位 ⊆ 核心区可达带（x,z ∈ [32,127]，非 far-north 剪影带）。
3. **不压建筑脚印**：测试侧以 `PrefabKit.footOf` 对照 `TOWN_MAP.prefab` 全清单断言零相交（镜像 town-map-core.test.js 先例——core 零依赖，校验在测试侧）。
4. **避让散布**：与 `TOWN_MAP.scatter` 全点位保持 ≥2 格（樱花/灯柱/路标不可站）。
5. **避让既有导览锚**：与 `TOWN_MAP.anchors` 七锚各 ≥2 格（交互点留玩家站位）。
6. **巡逻可走**：G01 相邻航点连线段不穿任何 prefab 脚印（逐段断言）。
7. **取数器**：静态锚任意 legIndex 恒返 waypoints[0]；G01 航点环取模正确（legIndex=-1/n/n+1 归一）；未知 id 抛错；返回值是拷贝（零突变红线）。
8. **跨表对账**（若 T-NPC-03 已落）：npcId 集 == 注册表 npcId 集；未落则对字面 14 键断言（anchor-core 不 import registry，依赖方向单向，桥接在测试）。
9. 收尾：`npm test` 全绿 + `npm run lint` 零错；禁触文件零改动。
